# modeler-loop: 숫자로 스스로 판단하는 실험 루프

루프 안에는 LLM 이 없다(크레딧을 쓰지 않음). 분기는 미리 적은 기준과 측정 숫자로 코드가 정한다. LLM(너)은 **계획을 쓰고, 멈췄을 때 판단하고, 채택을 기본값으로 옮기는** 세 자리에만 있다.

## 1. 계획 쓰기(`bench/loop/plan.json`, 돌리기 전에 커밋)
항목마다:
- `가설`: 무엇을 바꾸면 무엇이 오르는지. `반증`: 어떤 숫자면 거짓인지.
- `기준`: `{"부피_차": +x, "실루엣_차": -y}`(기준선 대비 평균). 개발과 확인에 같은 기준.
- `개발`: 고르는 데 쓰는 과제(`dev_*`, 씨앗 700~705). `확인`: 고르는 데 안 쓴 과제(`synth_*`, M0 600~605). 개발 과제로 고른 것을 확인 과제에서 다시 재야 과적합을 거른다.
- `후보`: `{"이름", "계열", "실루엣_보호"?, "설정"}`. 설정은 `bench/m0.py harness` 덮어쓰기(`body`·`parts`(부위 이름 또는 `*`)·`merge`). **한 후보에 한 가지만 바꾼다.**
- 실제 도면(들소·새)은 기준에 넣지 않는다(정답 없음). 채택 뒤 그림으로 확인한다.

## 2. 돌리기
```bash
"$PY" bench/auto_loop.py --hours 4 > bench/loop/run.txt 2>&1     # 뒤에서(run_in_background), 끝나면 알림
```
- 상태 `bench/loop/state.json`(측정은 캐시, 다시 켜면 이어서). 멈추려면 `bench/loop/STOP` 파일.
- 분기: 개발 PASS → 확인 → PASS 면 '채택 후보'. 부피가 줄면 같은 계열 건너뜀. 부피는 올랐는데 실루엣만 떨어지면 `실루엣_보호` 후보 먼저. ERROR 는 한 번 다시.
- 기다리는 동안 파일을 들여다보지 않는다(알림이 온다).

## 3. 끝났을 때(끝 코드)
- **0(계획 끝)·채택 후보**: 기본값으로 옮기기 전에 (가) 회귀 시험 추가, (나) 자체 시험 전부 PASS, (다) 실제 도면 그림 확인. 그다음 `docs/수정_기록.md`·`docs/교훈.jsonl`·커밋.
- **1(보류, `판단_필요.md`)**: 순서대로
  1. **진단**: 과제별·부위별 숫자를 본다(`state.json` 의 `과제별`, 필요하면 부위별 부피를 직접 잰다). 후보가 건드린 곳이 실제 오차가 큰 곳이었나? (단면틀 항목: 단면은 +0.03 뿐, 진짜 원인은 가려진 곳을 비었다고 본 것이었다.)
  2. **조사**: 원인을 모르면 웹 검색 3번까지(논문·기존 도구 먼저).
  3. **새 후보**: 가설 하나를 반증 조건과 함께 plan.json 에 새 항목으로. 기준을 실패에 맞춰 낮추지 않는다(바꾸려면 사용자 승인).
- **2(멈춤: 시간·STOP)**: 상태가 남아 있으니 다시 켜면 이어서.

## 하지 않는 것
- 루프 결과를 "좋아 보인다"로 채택하지 않는다. 확인 과제 PASS 만.
- 개발 과제에서 후보를 고르고 같은 개발 과제 숫자로 보고하지 않는다.
- 한 번에 여러 설정을 바꾼 후보를 만들지 않는다(무엇이 효과였는지 모름).
