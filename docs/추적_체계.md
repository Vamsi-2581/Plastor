# 추적 체계: 조사 → 결정 → 설계 → 구현 → 검증 (2026-10-30~)

사용자 지적: 조사 결과가 설계·구현에 실제로 들어갔는지 추적하지 않으니 조사가 잊힌다(크로스 컨투어·해부학 도구가 그랬다).
'조사 결과를 꼭 쓰라'고 적는 것으로는 안 된다. 그래서 구조화된 장부 + 자동 검사기 + 실행 증거로 묶는다.

## 파일
- `trace/registry.json` — 결정 장부(조사 하나 = 항목 하나, ID `R-` + 세 자리).
- `trace/evidence.jsonl` — 증거: 연결된 시험을 실제로 돌린 결과(끝 코드, 판정, 그때의 구현·시험 파일 지문).
- 검사기 `mh trace_check`, 증거 실행기 `mh trace_verify` (Rust, `rust/src/trace.rs`). MCP 도구 `verify_trace` 로도 쓸 수 있다.

## 항목 형식
```json
{"id": "R-###", "조사": "한 줄 조사 결과", "출처": ["docs/조사_업계관행.md", "https://…"],
 "상태": "채택 | 보류 | 기각 | 대기", "근거": "왜 그렇게 정했나",
 "다시_볼_조건": "보류·기각일 때 다시 볼 조건", "자리": "루프 항목·로드맵 자리(예: 4d, K3, R6)",
 "설계": ["docs/구현계획_통합.md"], "구현": ["rust/src/fit.rs"], "시험": ["tests/selftest_rust_fit.py"],
 "충돌": ["R-###"], "대체": "R-###"}
```

## 검사 규칙(검사기가 자동으로)
1. **형식**: ID 가 겹치지 않음, 상태는 넷 중 하나, 모든 항목에 근거. 보류·기각은 다시 볼 조건이 있어야 함.
2. **잊힘**: 대기(아직 정하지 않음)인데 자리가 없으면 FAIL. 조사가 어디에도 걸리지 않고 사라지는 것을 막는다.
3. **채택은 끝까지**: 채택이면 설계·구현·시험이 모두 있어야 한다. 하나라도 없으면 미설계·미구현·미검증.
4. **연결 검사**: 설계·구현·시험 파일이 있고, 그 파일 안에 ID 표지(예: 주석 `추적: R-###`)가 있어야 한다.
5. **실제 반영 검사(연결과 따로)**: 표지만 적고 기능을 안 만드는 편법을 막으려고, 연결된 시험을 `mh trace_verify` 가 실제로 돌린다.
   끝 코드 0 = PASS 인 증거가 있고, 그 증거의 구현·시험 파일 지문이 지금 파일과 같아야 '반영됨'. 파일이 바뀌었으면 '증거 낡음'.
6. **충돌**: 채택끼리 `충돌` 로 서로 묶여 있으면 FAIL. `대체` 된 항목이 아직 채택이면 FAIL.
7. **없는 ID**: 코드·문서에 장부에 없는 ID 표지가 있으면 FAIL.
8. **등록 안 된 조사 문서**: 조사 문서(`docs/조사_*.md`·`*_조사.md`·`자유조사_*.md`)가 어느 항목의 출처에도 없으면 FAIL.

## 판정
- 항목마다: 반영됨(채택 + 증거 PASS·최신) / 대기 / 보류 / 기각, 또는 문제(미설계·미구현·미검증·연결 끊김·증거 없음·증거 낡음·시험 FAIL·잊힘·충돌·형식).
- 전체 `mh trace_check {}`: 문제가 하나라도 있으면 FAIL(남은 일 목록을 그대로 보여 준다).
- **관문** `mh trace_check {"항목": "4e"}`: 그 자리에 걸린 항목만. 루프 항목을 '완료'로 적거나 '완료' 커밋을 하려면 이 관문이 PASS 여야 한다.
  커밋 메시지에 `루프 <항목> 완료`가 있으면 `tools/hooks/commit-msg` 가 관문을 돌려 PASS 가 아니면 커밋을 막는다.

## 원칙
- 조사와 결정은 다르다. 조사가 다 정답은 아니고, 채택하지 않은 이유도 남긴다.
- 연결됐다는 것과 실제 반영됐다는 것은 다르다. 반영은 실행한 시험의 PASS 로만 센다.
- 상태를 실패에 맞춰 바꾸지 않는다. 채택한 것을 못 만들었으면 채택·미구현으로 남기거나, 근거를 적고 보류로 내린다.
