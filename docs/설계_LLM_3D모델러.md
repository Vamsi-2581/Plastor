# 설계: Claude Code 같은 LLM 기반 3D 모델러 (2026-10-29)

사용자 요청: "우리 도구를 추상화하고, 클로드코드같은 LLM 기반 3d모델러 도구를 완성시킬 솔루션을 계획해봐. 3d 지오메트리, 트레이싱, 트랙킹, 기타등등 모든 필요한 키워드를 필요한 논문을 조사해봐".
목표 한 줄: **사람이 도면(정면·옆·뒤)을 주면, LLM 이 도구만 불러 도면에 충실하고 게임에 쓸 수 있는 3D 캐릭터(메시·텍스처·뼈대)를 만든다. 매 걸음 검사기가 판정하고, 막히면 스스로 조사한다.**

## 1. 추상화: 다섯 가지 틀

Claude Code 가 코딩을 잘하는 이유는 모델이 아니라 틀이다(파일·명령·시험·기록). 3D 모델러도 같은 틀이 필요하다. 지금 하네스에 있는 것을 이 다섯 틀로 다시 묶는다.

| 틀 | 뜻 | Claude Code 에서 | 지금 하네스 | 빈칸 |
|---|---|---|---|---|
| **상태(State)** | 작업물 전체. 다시 만들 수 있어야 함 | 저장소 파일 | 사양(build.json·트레이스 사양) + 결과 폴더 + 입력 지문 | 부위끼리의 관계(어디에 붙는지)를 담는 **부위 그래프**가 없다 |
| **연산(Op)** | LLM 이 부르는 일. 좌표를 받지 않음 | 편집·명령 실행 | 도구 층 `harness/api.py` 7개 + `build` 8단계 | 부위 단위 편집 연산(이 부위만 다시, 단면 바꾸기, 붙는 자리 옮기기)이 없다 |
| **검사기(Verifier)** | 판정 넷(PASS·FAIL·UNKNOWN·ERROR) | 시험·린트·빌드 | 독립 검사(높이·좌우), 3D 재투영, 합친 메시, 리깅 준비, 자체 시험 7종 | **모양 그럴듯함**(각진 머리 같은 것)을 재는 검사기가 없다. 텍스처 검사기도 없다 |
| **판단(Judge)** | 규칙으로 못 정하는 것만 LLM 에게, 잘게 쪼개서 | 사람 리뷰 | 빠진 재질 찾기(두 모델 가족 일치), 교정 후보(넣기·빼기·그대로), 그림 모순 결정 | 판단마다 **확신·근거 기록 형식**이 제각각 |
| **기억(Memory)** | 지난 실패를 다음 걸음에 | 커밋 기록·CLAUDE.md | 수정_기록, 교훈 jsonl(진단·부위 꼬리표), 카드(정 → 동), 막힘 시 조사 단계 | 교훈 검색이 꼬리표 일치뿐. 모델마다·도면마다 결과를 모은 **실험 장부**가 없다 |

설계 원칙(지금까지의 실패에서 나온 것)
- LLM 은 좌표를 쓰지 않는다. 이름·범위·선택만 준다(보라 삼각형, 좌표 그리기 실패).
- 판단은 쪼개고, 현재 답을 보여 주지 않고, 다른 모델 가족과 맞춰 본다(재질 묶음: 통째로는 0.81~0.85, 한 질문으로 0.787→0.930).
- 쉬운 경우는 규칙, 어려운 경우만 학습 모델, 엇갈리면 증거로(SAM 안전 검사, ToonOut 섞기 계획).
- 합성 정답 벤치마크로 먼저 재고, 실제 그림은 그림으로 확인한다(SAM 두 재질 귀처럼 벤치마크가 못 잡는 경우가 있다).

## 3. 완성까지 로드맵(각 단계 채택 기준은 돌리기 전에 정함)

| 단계 | 할 일 | 채택 기준 |
|---|---|---|
| R1 형상 바꾸기 | 매끈한 일반화 원통 맞추기(뿔·본체), 복셀로 되돌리지 않음 | 합성 휜 뿔 새 씨앗: 실루엣 ≥ 0.98, 부피 IoU ≥ 둥근 헐, 거칠기 ≤ 5°. 합성 머리 부피 IoU > 둥근 헐 |
| R1.5 크로스 컨투어 추론(사용자 "트레이싱하면서 크로스 컨투어 라인까지 추론") | 셀 셰이딩 톤 띠 경계 = 같은 밝기 선(isophote) → 빛 방향 추정 → 면 방향(법선) 복원 → 단면 곡선 생성 → R1 단면 제약. 근거: Inverse Toon Shading(Xu·Gingold·Singh 2015, 2016 높이장), CrossShade(SIGGRAPH 2012) | 합성 장면(빛·톤 문턱·정답 법선을 앎)에서 복원 법선의 각 오차 중앙값 ≤ 15°, 그 단면으로 만든 뿔·머리의 부피 IoU 가 단면 제약 없는 것보다 높음. 빛 방향이 뷰끼리 어긋나면 그림 모순으로. **이름 → 단면 틀**(사용자 "사과의 실루엣이 있으면 사과라고 판단해서 둥글게"): 피아식별로 정한 부위·물체 이름에 단면 틀을 붙임(머리·사과 = 공, 뿔·꼬리 = 가늘어지는 둥근 관, 귀 = 오목한 판, 천·끈 = 납작한 띠, 기계 = 각진 단면). 그림자 근거가 있으면 그것이 먼저, 선화면 틀이 주 근거, 그림에 단면선이 있으면 그 선이 가장 강함. 틀은 기본값일 뿐이고 실루엣·그림자와 어긋나면 그림을 따름(흔한 모양을 믿는 위험). 검증: 공·관·판이 섞인 합성 장면에서 이름대로 고른 단면이 정답 부피에 더 가까움 |
| R2 부위 그래프 | 사양에 부위·붙는 자리·좌우 짝을 적고, 부위 단위 연산(다시 만들기·단면 바꾸기) 추가 | 들소·새 두 도면을 그래프로 다시 만들어 단계 1~5 판정이 같거나 좋음. 부위 하나만 다시 만들 때 다른 부위 메시가 그대로(지문 같음) |
| R2.5 형태 판단 | 도면 오류를 무시할 근거: 뷰 합의·대칭·부위 관계·형태 사전·출처 신뢰, 독립 근거 둘 + 두 모델 가족 일치일 때만 고침(`docs/설계_형태판단.md`) | 오류 주입 합성 벤치마크: 정밀도 ≥ 0.9, 의도된 특이함 오교정 ≤ 0.05, 재현율 ≥ 0.6, 기존 벤치마크 하락 없음 |
| R3 배경·부위 분할 섞기 | ToonOut + 규칙 섞기, 같은 색 하위 부위 경계(선·톤 경계 + SAM) | 체크무늬 정답 벤치마크에서 섞기 ≥ 규칙(한 항목 +0.02), 한 색 배경 하락 없음 |
| R4 모양 그럴듯함 검사기 | 법선 일관성(Eval3D 방식), 단면 둥글기, 위에서 본 윤곽, 두 모델 가족 그림 판정 | 합성: 일부러 각지게 만든 메시와 둥근 메시를 갈라냄(시험), 들소 16차 각진 머리를 FAIL 로 잡음 |
| R5 텍스처 | 정면·옆 투영 + 재질별 평면색, 가려진 면은 재질 지도로 메움 | 투영한 텍스처를 다시 렌더한 정면·옆 그림이 도면 색과 재질별 평균 색차 ΔE < 10 |
| R6 리토폴로지·리깅 | Blender QuadriFlow, Rigify 사족 메타릭 맞추기 | 사각면 비율 ≥ 0.95, 실루엣 하락 ≤ 0.01, 리깅 준비 검사 PASS 유지 |
| R7 트래킹 | 영상·참고 동작 → 뼈대 움직임 조사부터 | 조사 결과로 기준을 정함(지금은 UNKNOWN) |
| R8 과제 묶음·장부 | 도면 → 모델 과제 10개 이상(케라투라 머리 128종 시트 등), 모델(Claude·Codex)·설정별 결과 장부, 교훈 검색 개선 | 같은 과제를 다시 돌렸을 때 결과가 같음(지문), 장부에서 실패 유형별 개수 집계 |

순서 이유: 지금 사람이 가장 먼저 보는 문제는 **모양**(각진 머리·계단)이라 R1 이 먼저다. R2 는 R1 결과를 부위 단위로 고칠 수 있게 하는 틀이다. R4 가 있어야 R1·R2 가 좋아졌는지 사람 눈 없이 잰다.

## 5. 심화 조사(사용자 "더 깊게 검색하세요")

### 5.1 이번에 메운 빈칸

### 5.2 로드맵 고침
- **R2 부위 그래프** → aDSL·Procedura 처럼 **관계 연산**(붙이기·좌우 짝·위쪽/옆쪽)과 **부위마다 받아들이기 검사**(합쳐짐·떠 있지 않음·실루엣)로.
- **R4 검사기** → 고정 시점 묶음 + 법선 그림 + 와이어프레임, 앞뒤 비교, 한 번에 문제 하나(aDSL·Procedura 의 비평 규칙).
- **R6** → 리토폴로지(QuadriFlow) 다음에 PartUV 로 부위 단위 UV.
- **R7 트래킹** → "만든 뼈대(FBX) + 참고 영상 → MoCapAnything → BVH → Blender 에서 재생"을 시험 과제로. 채택 기준: 사족 시험 영상 하나에서 뼈대가 따라 움직이고 메시가 찢어지지 않음(가중치 0 정점 0%, 관절 각 이상값 없음), 판정은 그림 확인 + 숫자.

### 5.3 여전히 못 찾은 것(UNKNOWN)
- MoCapAnything 의 CPU 실행 가능 여부와 가중치 크기.
- 게임 엔진 기준(UV·변형·면 수 한도)으로 화가식 메시 생성기를 잰 독립 평가.
- 셀 셰이딩(툰) 전용 텍스처 생성의 CPU 방법.

## 4. 못 찾은 것(UNKNOWN, 1차 조사 때)

## 6. 숙련 모델러처럼 일하기(사용자 "단순히 트레이싱한 걸 3D 로 뽑지 않고 아트 감각과 판단에 의거한 숙련된 모델러처럼")
### 6.1 조사
- **정면으로 다룬 연구는 못 찾음**: 숙련자 공정(블록아웃 → 1차 형태 → 2차 형태 → 3차 세부)을 따라 하는 AI 연구는 없었다(UNKNOWN). 이 하네스가 채울 자리.
- 숙련자의 방식을 배우는 쪽: BlenderLore(튜토리얼 영상 → 시간표 붙은 근거 → 작업 절차 재구성 → 실행되는 Blender 코드, 제3자 소개 [SkillsLLM](https://skillsllm.com/skill/blenderlore), 원 저장소 확인 필요), VideoCAD([arXiv 2505.24838](https://arxiv.org/pdf/2505.24838)), Fusion 360 Gallery([arXiv 2010.02392](https://arxiv.org/pdf/2010.02392)).
- 모델러처럼 나눠 만들기: Planner-Actor-Critic(숙련자는 부위로 나누고 묶어 편집 가능하게 둔다, [arXiv 2601.05016](https://arxiv.org/pdf/2601.05016)).
- 아트 판단: 통째 판정보다 **항목별 점수**가 정보가 많다([arXiv 2609.27110](https://arxiv.org/pdf/2609.27110)), 모델끼리 형태 인상이 일치하는지 감사([arXiv 2608.25876](https://arxiv.org/pdf/2608.25876)), 에이전트 창작 조사([arXiv 2608.28122](https://arxiv.org/pdf/2608.28122)).
### 6.2 적용(R4 검사기·카드에 넣음)
1. **공정 순서를 카드로**: 큰 덩어리·비율 → 1차 형태(실루엣·주요 면) → 2차(부위·근육 덩어리) → 3차(세부). 앞 공정 관문을 통과해야 다음으로.
2. **아트 원칙 항목 점수**(두 모델 가족이 고정 시점 렌더를 보고 항목마다): 실루엣 읽힘(검은 실루엣·축소), 비율, 형태 언어 일관(둥긂/각짐), 큰-중-작 대비, 무게감·접지, 대칭/의도된 비대칭, 도면 스타일 유지. 통째 "좋은가"는 묻지 않는다.
3. **숙련자 지식 모으기**: 튜토리얼 영상에서 절차 뽑기(BlenderLore 식)를 카드·교훈·스킬로.
4. **충돌 규칙**: 도면 > 아트 판단. 아트 판단은 도면이 말하지 않는 곳(뒤·안쪽·단면·세부)에서만.
- 검증 기준: 같은 모델의 '좋은 판'과 일부러 망친 판(비율 틀어짐·실루엣 뭉개짐·형태 언어 섞임)을 항목 점수가 가려냄(두 가족 일치 ≥ 0.8), 들소 16차 각진 머리를 '형태 언어'·'실루엣' 항목에서 낮게 잡음.
