# 루프 작업 목록 v2 (2026-10-30~)

사용자: "모든 구현을 나한테 묻지 않고 계속 조건부로 분기 루프 엔지니어링 짜서 해라".
깨어날 때마다 이 파일만 읽고, 아래 '분기 규칙'으로 다음 걸음을 정한다. 사용자에게 묻지 않는다. 결정은 이 파일·`docs/수정_기록.md` 에 이유와 함께 적는다.
기준 문서: `docs/진단_방향재검토.md`(무엇이 맞고 틀렸나), `docs/구현계획_통합.md`(K 단계), `docs/설계_러스트.md`(Rust 지도). 옛 목록(v1)은 git 이력.

## 분기 규칙(깨어날 때마다 위에서부터)
0. **사용량**: 주간 ≥ 95% 또는 5시간 ≥ 90% → 새 일 시작 금지, 돌던 계산만 거두고 5시간 초기화까지 잠. 주간 ≥ 98% → 하던 일 커밋, 루프 멈춤, 한 줄 보고.
1. 뒤에서 도는 계산이 있음 → 끝났으면 3 으로, 아니면 잠(알림이 깨움, 대비 1800초).
2. 지금 항목의 기준이 문서에 없으면 → **기준부터 적고 커밋**(돌리기 전에). 그다음 구현.
3. 판정:
   - PASS → 기본값 채택 + 회귀 시험 + 기록 + 커밋 → 다음 항목.
   - FAIL·원인 진단됨 → 한 번에 하나만 바꿔 다시(시도 수 +1, 최대 2).
   - FAIL·시도 2 번 넘음 또는 원인 모름 → 조사(웹 3번까지, 논문·기존 도구 먼저) → 반증 조건 있는 가설 하나 → 한 번 더 → 그래도 FAIL 이면 '보류'(이유·다음 단서) → 다음 항목.
   - ERROR → 환경·코드 고치기 1번, 또 ERROR 면 보류.
   - UNKNOWN → 판정 수단(검사기·합성 정답)을 먼저 만들거나 보류.
   - 기준을 실패에 맞춰 낮추지 않는다. 시험 방식에 결함이 있으면 고치되 그 사실과 기준 숫자를 그대로 적는다.
4. 앞 항목 결과가 뒤 항목의 전제를 바꾸면 순서를 바꾸고 이유를 적는다.
5. 안전: 오픈소스 모델·도구 내려받기·설치는 묻지 않고 진행(사용자 승인), 구매 없음, 외부 게시(GitHub 공개)는 직전에 공개 범위만 확인, 케라투라 파일 안 건드림. 하위 에이전트 Sonnet 동시 2개, Codex 는 판정에만.
6. 항목마다 끝에 커밋(한국어, Co-Authored-By 줄).
