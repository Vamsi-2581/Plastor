# 진단: 하네스 방향 재검토와 숙련 모델러의 사고체계 (2026-10-30)

요청: 지금까지의 방향을 냉정하게 진단하고, 숙련 모델러의 사고를 실행 가능한 절차·도구로 바꾸는 구조를 제안. **새 구현은 이 보고 뒤에.**
표시: **[관찰]** 이 저장소에서 잰 것, **[외부]** 확인한 연구(입증 범위 함께), **[추론]** 기술적 추론, **[가설]** 검증 안 됨.

## 1. 냉정한 진단

### 1.1 올바른 방향
| 접근 | 근거 |
|---|---|
| LLM 은 좌표·정밀 수를 쓰지 않고, 도구가 잰다 | [관찰] 좌표 그리기 실패(보라 삼각형). [외부] LLM CAD 는 문법이 맞아도 부품 위치·값 하나가 틀림([arXiv 2603.11831](https://arxiv.org/pdf/2603.11831), [BenchCAD](https://arxiv.org/pdf/2605.10865)), 측정값으로 바깥 고리를 돌리면 크게 나아짐([CADSmith](https://arxiv.org/pdf/2603.26512), 챔퍼 거리 28.37 → 0.74, CAD 범위) |
| 판정은 실행한 검증기, 기준은 미리, 재현은 지문 | [관찰] 이 규율로 하네스 버그 셋을 잡음: 합집합이 본체를 지움(수정_기록 44), 숨은 입력(45), 채점기 오류(겹친 조각·복셀 크기). 내 틀린 진단 둘(겹친 구 부피 합, 렌더 가짜 선)도 숫자 교차로 잡음. [외부] 외부 되먹임 없는 자기 수정은 불안정([CRITIC](https://arxiv.org/pdf/2305.11738)) |
| 부위로 나누고 부위마다 다른 도형 | [관찰] 하네스 없는 Sonnet 이 타원체·휜 관 조립으로 부피 0.90(합성 2종, 정답이 타원체라 유리). [외부] 옆 한 장 동물 스케치를 부위 윤곽·좌우 짝·암시 곡면 합치기로 복원([Entem 2015](https://hal-univ-tlse3.archives-ouvertes.fr/INRIA/hal-01073059)), 모양을 '부위 상자 조립 프로그램'으로 쓰면 편집 가능하고 그럴듯함([ShapeAssembly](https://arxiv.org/pdf/2009.08026), 가구 데이터 범위) |
| 판단을 잘게 쪼갬 | [관찰] 재질 묶음 통째 0.81~0.85 → 한 질문 0.787→0.930(귀) |
| 실루엣 안쪽 정보(단면선·톤)를 쓰려는 방향 | [외부] 단면 곡선으로 법선장 추정, 사용자 연구·정답 법선으로 검증([CrossShade, SIGGRAPH 2012](https://hal-univ-tlse3.archives-ouvertes.fr/INRIA/hal-00703202)), 셀 셰이딩 같은 밝기 선 → 법선·높이장([Inverse Toon Shading](https://cragl.cs.gmu.edu/inversetoon/Inverse%20Toon%20Shading-%20Interactive%20Normal%20Field%20Modeling%20with%20Isophotes%20(Qiuying%20Xu,%20Yotam%20Gingold,%20Karan%20Singh%202015%20SBIM)%20presentation.pdf)). **단 우리는 아직 안 씀** |

### 1.2 잘못된 방향(목표를 왜곡하거나 근본 한계를 못 넘음)
| 접근 | 왜 | 근거 |
|---|---|---|
| **두 뷰 헐(실루엣 교집합)을 본체 생성의 중심으로** | 실루엣을 완벽히 맞춰도 형상은 틀린다. 높이마다 단면이 직사각형이 되고, 가려진 곳은 비거나(채우면 부풂) 한다 | [관찰] 하네스 실루엣 0.92~0.97 인데 부피 0.39~0.63, 3/4 폭 비 0.95~0.99(상자; 자유 Sonnet 0.76~0.78), 거칠기 12~14°(자유 6~7°). 단면을 타원으로 바꿔도 +0.03(루프 '단면틀') |
| **둥근 헐(쓸기 + 실루엣 채우기)** | 정답 뿔의 47~49% 만 덮음, 그냥 헐(0.60)보다 나쁨(0.33~0.35) | [관찰] 수정_기록 46 |
| **'도면 > 아트 판단' 절대 규칙** | 도면이 틀렸을 때 틀린 것을 정확히 복제하는 것이 최선이 됨. 지금 지표도 그것을 상으로 줌(아래 4장) | [추론] + 사용자 지적. [외부] 스케치 복원은 평행·직교·대칭 같은 규칙성을 '골라서' 적용해 그림의 부정확함을 고침(True2Form, SIGGRAPH 2014: 원문은 이번에 확인 못 함, 토론토 그룹 발표 자료에서 '규칙성을 골라 적용하는 곡선망 복원'으로 소개된 것만 확인, 곡선망 범위) |
| **실루엣 IoU·도면 일치율을 주 지표로** | IoU 가 높아도 사람 눈엔 나쁜 메시 | [외부] 크게 일그러진 메시가 IoU 0.96 인데 사용자 점수 2.74/5([SAUCD](https://arxiv.org/pdf/2403.01619)), IoU·챔퍼는 사람 평가와 상관이 낮음([Pix3D](https://arxiv.org/pdf/1804.04610), [arXiv 2512.01380](https://arxiv.org/pdf/2512.01380)) |
| **트레이싱 정밀도에 많은 시간**(배경·재질·SAM·k·톤) | 형상 품질의 병목이 아니었다 | [관찰] 트레이스로 만든 헐 = 정답 마스크로 만든 헐(머리·뿔 IoU 같음). 실루엣은 이미 0.97 |
| **하네스 복잡도 증가**(카드·스킬·루프·문서 20개 넘음) | 모델 품질 개선 없이 늘었다 | [관찰] M0: 하네스 결과가 하네스 없는 Sonnet 보다 부피가 낮다 |

### 1.3 불충분한 방향(일부 타당, 핵심 능력이 빠짐)
| 접근 | 빠진 것 |
|---|---|
| 공정 순서(블록아웃 → 1차 → 2차 → 세부) 카드 | 순서는 숙련자의 '결과'이지 능력이 아니다. 각 단계에서 **무엇을 보고 무엇을 정하는지**(구조 가설·원형 선택·오류 분류)가 없다 [추론] |
| 형태 판단·의도 파악 루프(설계만) | 2D 트레이스 조각을 빼고 두는 수준. **3D 구조 가설을 세워 도면에 비춰 고르는** 단계가 아니다 [추론] |
| 아트 비평(설계만) | 숫자 대리값은 있음(3/4 폭·거칠기). 그림 판정은 LLM 능력 미검증(K0 진행 중) |
| Rust 이전(P1) | 속도(복셀화 80~170배)는 얻었지만 **품질과는 무관** [관찰] |
| 해부·투시 블록(설계도 형식) | 형식만, 쓰는 곳·검증 없음 |

### 1.4 미검증 가설
| 가설 | 상태 |
|---|---|
| LLM 이 부위·연산자·아트를 맞게 판단한다 | K0 측정 중(합성 정답 문항 50여 개, 두 가족 × 순서 A·B) |
| **두 모델 가족이 같으면 옳다** | [외부] 모델이 강해질수록 **실수가 서로 닮아 간다**, 판정자는 자기와 닮은 모델을 편애([Great Models Think Alike, ICML 2025](https://arxiv.org/pdf/2502.04313)). 즉 두 가족 일치는 독립 근거가 아니다 → 정답 아는 '보정 문항'을 섞어 오답 상관을 재야 함 |
| 톤 띠(크로스 컨투어)가 깊이를 잡는다 | K3 에 반증 기준만 적음, 미실행 |
| SDF 원형 연산자 맞추기로 부피 ≥ 0.8 | K2 미실행. 근거는 Sonnet 0.90(2종)뿐 |
| 단계 카드·교훈이 LLM 성과를 올린다 | 카드 있음/없음 비교를 한 적 없음 |

### 1.5 폐기할 접근
둥근 헐(이식 포함), 고리 케이지 확장, 2단계 핸들 다듬기(fitloop: [관찰] 들소에서 이득 없음, 정면 IoU 0.918→0.914), 단면을 헐 안 타원으로(+0.03), 표면 다듬기 5종, 크기 문턱 SAM 자동, Laya Vision, SAM 쪼개기, '실루엣 맞추기'를 성공 기준으로 쓰는 것.

## 2. 숙련 모델러의 핵심 능력(순서가 아니라 능력으로)
| 능력 | 하는 일 | AI 에서 누가 | 지금 |
|---|---|---|---|
| **지각** | 실루엣 + 안쪽 선(단면선·주름·톤 경계)·가림 순서(무엇이 앞)·덩어리 경계를 읽음 | 도구(트레이스·톤 지도·가림 순서·digest), LLM 은 이름만 | 실루엣만 씀. 톤·가림 순서 없음 |
| **구조 추론** | "이것은 머리뼈 위 공 + 주둥이 덩어리, 뿔은 뿌리에서 뒤-위로 휜 관" 같은 3D 가설, 가려진 곳은 원형으로 채움, **가설을 여럿** | LLM(원형·관계 선택) + 도구(맞추기) | 없음(마스크 → 헐 한 가지) |
| **해석** | 도면 요소를 5분류: 정체성·의도된 과장·불확실·오류·충돌, 각각 근거 | LLM(분류 제안) + 도구 증거(뷰 사이 어긋남·대칭·해부 비율) | 그림 모순 진단만 |
| **판단** | 가설 비교: 모든 뷰에서 동시에 그럴듯한가(재투영), 형태 사전·해부에 맞나, 미적 위계(대·중·소) | 도구 점수 + LLM 은 동점일 때만 | 없음 |
| **실행** | 문제에 맞는 연산자(관 = 커브 쓸기, 덩어리 = 서브디브·메타볼, 판 = 두께 준 면), 순서, 실패 시 전략 전환 | 도구(연산자 라이브러리) + LLM(선택·전환) | 헐 하나 |
| **자기 점검** | 돌려 보고 3/4·위에서 덩어리감 확인, 와이어 확인 | 도구(3/4 폭·거칠기·와이어 그림) | K1 에서 생김 |

[외부] 단일 그림 캐릭터 복원 연구들은 공통으로 **골격(뼈대)이 깊이 모호성을 푸는 열쇠**로 쓴다([Bessmeltsev 2015](https://history.siggraph.org/?p=114420), [Buchanan 2013](https://fileadmin.cs.lth.se/graphics/research/papers/2013/characterRecon/buchanan13-ACMR-SBIM.pdf)). 모델 시트의 뷰끼리 모순을 다루는 연구는 이번 조사에서 찾지 못함(없다는 뜻이 아님).

## 3. 지금 하네스가 숙련자처럼 못 하는 이유(결핍)
1. **3D 구조 가설의 표현이 없다.** 실행 경로가 '마스크 → 헐'이라 판단이 들어갈 자리가 없다.
2. **형태 원형(사전)이 없다.** 가려진 곳·한 뷰에만 보이는 곳을 원형으로 채우지 못한다.
3. **실루엣 안쪽 정보를 안 쓴다**(톤 띠·단면선·가림 순서).
4. **도면 요소 분류가 없다.** 모든 픽셀을 같은 무게로 맞춘다 → 오류도 복제.
5. **평가가 도면 일치에 묶여 있다.** 실제 도면은 '트레이스 대비'라 정답이 아니고, 도면 오류를 고친 모델은 점수가 내려간다.
6. **전략 전환이 없다.** 한 방법이 실패해도 같은 방법의 숫자만 바꿨다(루프 단면틀).

## 4. 평가의 근본 한계(질문에 답)
| 질문 | 답 |
|---|---|
| 실루엣이 완벽해도 형상이 틀릴 수 있나 | **예** [관찰] 실루엣 0.97·부피 0.61·3/4 상자. [외부] IoU 0.96 인 일그러진 메시(SAUCD) |
| 유효한 메시가 예술적으로 형편없을 수 있나 | **예** [관찰] 닫힘·한 덩어리 PASS 인 상자 머리(들소 16차 카드 1~5 PASS) |
| 도면 오류를 고친 모델이 낮은 점수를 받나 | **예** [추론] 지금 지표는 도면(트레이스)과의 일치라, 비켜 그린 뿔을 고치면 IoU 가 떨어진다 → **정답을 3D 로 둔 '오류 주입 과제'로만 공정하게 잴 수 있다** |
| 지표 최적화가 품질을 해치나 | **예** [관찰] 둥근 헐은 실루엣 1.000 을 맞추려다 부피·매끈함을 잃음(표면 다듬기 5종이 실루엣 < 0.99 라 기각된 것도 같은 함정) |
| 두 AI 가 같은 잘못에 동의하면 | 지금은 못 잡는다. [외부] 실수 상관(CAPA). 대책: 정답 아는 보정 문항을 판단마다 섞어 두 가족 오답 상관을 재고, 상관이 크면 '일치'를 근거로 세지 않음. 도구 측정값과 사람 표본 검사를 최종 근거로 |
→ 평가는 점수 합이 아니라 **진단표**여야 한다: 부피·3/4 폭·거칠기·랜드마크·도면 오류 처리(주입 과제)·사람 쌍비교, 그리고 실패한 항목이 어느 결핍(1~6)에서 왔는지 붙인다.

## 5. 대안 아키텍처: 가설을 세우고 도면에 비춰 고르는 모델러(분석-합성)
```
관찰(도구) → 증거표: 실루엣·톤 띠·가림 순서·뷰 사이 어긋남·digest 숫자
해석(LLM)  → 설계도: 부위 목록·원형(덩어리/관/판/골격)·관계·도면 요소 5분류와 근거, 구조 가설 2~3개
생성(도구) → 가설마다 원형 연산자 맞추기: 손실 = 분류 가중 도면 증거(정체성 강, 불확실 약, 오류 0) + 원형 사전 + 해부 타당성
비교(도구) → 가설별 진단표(재투영·사전 이탈·3/4·거칠기) → 고름. 동점·애매만 LLM·사람
실행(Blender) → 고른 가설을 편집 가능한 객체로: 관 = 커브 + 베벨, 덩어리 = 서브디브/메타볼, 판 = 두께, 골격 = 아마추어
```
- 크로스 컨투어의 쓰임: (가) 맞추기 손실에 톤 띠 항(K3), (나) **Blender 에서 가설 메시를 등간격 평면으로 잘라 단면 고리를 그려 도면 위에 겹친 그림** → 형태 흐름·비틀림을 사람·LLM 이 본다, (다) 같은 빛으로 셀 셰이딩 렌더해 도면 톤 띠와 비교(숫자).
- 제어 언어: 사용자 조건 "제어·하네스는 TypeScript 중심, MCP" ↔ 앞선 지시 "도구 전체를 Rust 로". **[추론] 제안**: TypeScript = MCP 서버·작업 흐름, Rust = 계산(맞추기·복셀·채점, 이미 있음), Blender Python = 실행. 지금 파이썬 하네스 층은 TS 로 옮기는 대상. **사용자 확인 필요.**

## 6. 우선순위(효과 대비 비용)

## 7. 검증 실험(같은 과제로 기존 대 개선)
- **실험 A 형상**: 3D 정답 크리처 12종(씨앗 새로), 도면 렌더 + 그중 6종은 오류 주입(뷰 높이 어긋남·비켜 그린 짝 부위·약한 투시). 비교: ② 지금 하네스, ① 하네스 없는 자유 작업(Sonnet), ③ 원형 맞추기. 지표: 3D 정답 대비 부피 IoU·3/4 폭 비·거칠기·랜드마크(도면 대비가 아님), 오류 주입 과제는 3D 정답 대비로만. 사람 블라인드 쌍비교 6쌍. **기준(미리)**: ③ 이 ② 보다 부피 +0.15, 3/4 폭 비가 정답과의 차 절반 이하, 사람 쌍비교 과반, 오류 주입 과제에서 ③ 이 ① 이상.
- **실험 B LLM 판단**: K0(진행 중). 맡길 판단과 도구로 넘길 판단을 가른다.
- **실험 C 두 가족 일치의 함정**: K0 문항에서 두 가족이 **같이 틀린** 비율과 우연 기대치를 비교(CAPA 식). 크면 '두 가족 일치 = 확정' 규칙을 버린다.
