## 2. 단계(앞 단계가 뒤 단계의 판정 수단을 만든다)
각 단계 기준은 돌리기 전에 이 문서에 적고 커밋한다. 개발 과제(dev_*)로 고치고 확인 과제(synth_* = M0)로 판정. 실제 도면은 그림 확인.

### K0 LLM 능력 재기(사용자 "LLM 의 한계를 조사하고 약한 부분을 도구로 보완해라", `docs/조사_LLM한계.md`)
- 보완 도구(만듦, `tests/selftest_aids.py` 5개 PASS): `digest`(숫자 요약: 조각 수·넓이·H 범위·대칭), `zoom`(부위 이름으로 원래 해상도 확대 + 조각 색 테두리), `judge`(재현율·순서 뒤집힘·가족 카파 → 확정/UNKNOWN).
- 잴 것(합성 정답, 하위 에이전트 Sonnet + Codex, 순서 A·B 각 2번 = 문항당 8답, `judge` 로 모음). 기준(돌리기 전):
  1. 부위 알아보기(있다/없다, 몇 개): 정확도 ≥ 0.9 이고 `judge` 확정 비율 ≥ 0.8 → 맡김. 아니면 `digest` 숫자로만.
  2. 연산자 고르기(덩어리·관·판): 정확도 ≥ 0.9 → K4 에서 LLM 이 고름. 아니면 이름 → 틀 표를 기본으로, LLM 은 예외만 제안.
  3. 작은 부위 보이기: 귀 크기를 0.5·0.75·1배로 줄인 합성에서 '귀가 있다' 정답률, 전체 그림 대 `zoom` 그림. 예측: `zoom` 이 가장 작은 크기에서 +0.2 이상. 못 미치면 zoom 효과 없음으로 기록.
  4. 아트 판정(좋은 판 대 일부러 망친 판: 상자형·계단·비율 틀림): 정확도 ≥ 0.8, 가족 카파 ≥ 0.6 → K6 에서 그 항목을 LLM 이 판정. 아니면 숫자 대리값만.
  5. 재현: 같은 문항 재현율 평균 ≥ 0.9, 순서 뒤집힘 평균 ≤ 0.1(넘으면 그 판단은 늘 `judge` 를 거친다).
- 비용: 문항 수를 작게(항목당 12문항 안팎). 주간 사용량이 70% 를 넘어 있어 K0 측정 실행은 사용자에게 먼저 묻는다.
- **실행 전 바꿈(2026-10-30, 사용자 "K0 지금", 돌리기 전)**: 문항당 답을 8 → **4**(두 가족 × 순서 A·B 한 번씩, 비용). 재현율 = 4답 중 다수 비율, 순서 뒤집힘 = 같은 가족 A·B 가 다른 비율. 기준 숫자는 그대로.
- 문항(정답은 합성 장면에서): 세트 1 부위(씨앗 800~809 전체 그림, 갈기 있나·볏(정수리 혹) 있나, 20문항), 세트 2 연산자(씨앗 800~803, 이름을 숨긴 부위 확대 그림 → 덩어리·관·판, 12문항), 세트 3 작은 부위(귀 크기 0·0.5·1배 × 씨앗 820~823, 전체 그림 대 `zoom`(머리 둘레) 그림, '귀가 있나', 24문항, 기준 3 은 0.5배에서 zoom − 전체 ≥ +0.2), 세트 4 아트(M0 합성 6종: 정답 도형 렌더 대 하네스 결과 렌더 짝, 좌우 바꿔 '형태가 더 잘 만들어진 쪽', 6문항).
- Claude 쪽 = 하위 에이전트 Sonnet, Codex 쪽 = `codex exec -s read-only -i 그림들`. 둘 다 정답·하네스 코드를 보지 못하게 문항 폴더만 준다.

- **K1 기준(돌리기 전, `tests/selftest_metrics.py` 끝 코드 0 = PASS)**:

  5. M0 확인 과제 다시 채점 시 지문·기존 점수 그대로(새 항목은 덧붙이기만).

### K2 Rust SDF 연산자·맞추기·조립(옛 S1·S2·S3, P2 일부)
- 크레이트 나누기(J04): `core`(격자·npy·좌표틀·형태 연산) · `sdf`(연산자·조립·표면 뽑기) · `fit`(손실·최적화) · `check`(복셀화·채점) · `tool`(도구 층).
- 연산자: 덩어리(초타원체, 여러 개 합), 관(중심선 + 반지름 변화 + 초타원 단면), **판**(귀·지느러미, A03 빠졌던 것).
- 맞추기 손실: 보이는 픽셀 불일치 + 가려진 픽셀 '상관없음' + 대칭·매끈함 벌점 + **뷰마다 작은 어긋남 허용**(손그림 시트는 뷰끼리 안 맞음, A09: 정면 하나만 믿고 나머지를 버리던 것 대신) + **한 뷰에만 증거 있는 부위는 다른 뷰 폭을 지어내지 않고 두께 사전값**(A08).
- 조립: SDF 합집합(부드러운 이음 smooth-min) → 한 번에 표면 → 늘 한 덩어리(불리언 실패 구조적으로 없음).
- K2a 뿔(관): 확인 과제 뿔 실루엣 ≥ 0.95, 부피 IoU ≥ 0.80, **거칠기 ≤ 5°**, 한 덩어리(9.1 정의 그대로 + 거칠기).
- K2b 귀(판): 확인 과제 귀 부피 IoU ≥ 0.75, 실루엣 ≥ 0.95(지금 하네스 0.49~0.52).
- K2c 조립: 몸 수 1, 합친 실루엣 하락 ≤ 0.01.
- K2d 머리(덩어리, 톤 항 없이): 머리 부피 IoU 를 잰다(판정은 K3 에서 톤 항 켬/끔 비교로).

### K3 크로스 컨투어·톤(옛 R1.5·S1b·S2)
- 톤 지도(트레이스의 재질별 3톤, 색면 분할 B07) → 빛 방향 추정(합성 오차 ≤ 10°) → 맞추기 손실에 톤 띠 항 → 법선·단면 곡선 복원(B05)해 설계도 단면 모양 채움.
- 이름 → 단면 틀 완성(B06): 공·관·판·띠·각진 단면, 그림 근거(단면선 > 톤 > 이름 틀) 순.
- 기준: 확인 과제 머리 부피 IoU ≥ 0.80 **그리고** 톤 항 켬 − 끔 ≥ +0.03(9.2 그대로). 뿔 단면(S1b): 켬이 끔보다 부피 높고 실루엣 하락 ≤ 0.005. 명도 일치 잔차(B08)를 보고.

### K4 설계도와 LLM(옛 M1·M2·R2)
- 설계도 JSON(`docs/설계도_형식.md`): 부위·연산자 종류·붙는 곳·짝·단면 틀·출처·확신 + `해부`(뼈 표지·비율) + `투시`(뷰별 정사영 징후·빛 방향). LLM 은 이름·종류·관계만, 숫자는 도구.
- 설계도 검사(만들기 전): 단면을 비춰 트레이스 폭과 맞는지, 짝 대칭, 붙는 곳이 부모 표면 안.
- 부위 단위 연산(좌표 없음): `rebuild(부위)`, `section_set`, `scale_rel`, `attach`, `mirror` + 관계 연산(위쪽·옆쪽, E07). 부위 하나만 바꾸면 다른 부위 지문 같음.
