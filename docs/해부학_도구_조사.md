# 해부학·모델링 도구 조사 (2026-10-28)

**방법:** `gh api`로 저장소 파일 목록·소스·데이터를 읽었다(읽기 전용). **설치·실행은 하지 않았다.** 따라서 아래 모든 항목에서 **"실제 실행 검증"은 0건**이다. 상태 표기: 구현 확인(소스에서 코드 확인) / 문서상 주장 / 개발 예정 / 미구현 / 확인 불가.
기존 개발(`fitloop.py`, `tests/selftest.py`, `SKILL.md`)은 건드리지 않았고, 이 조사로 바꾼 코드는 없다.

## 한 줄 결론

**해부학 데이터를 줄 기존 MCP는 사람용뿐이고 동물용은 찾지 못했다. Blender MCP 3종은 우리 fitloop 을 대체하지 못한다. 지금 도입할 외부 도구는 없고, 해부학은 "참고자료 → 우리 규칙 JSON" 경로로 별도 모듈로 넣는 것이 맞다.**

## 4. 기존 하네스와의 관계

### 중복되는 기능
- 메시 편집·렌더·정점 그룹·Lattice: 이미 Blender 내장을 직접 사용 중(MCP 불필요).
- 비교 체크포인트·복원: fitloop `stepNN.blend` + 정점 해시.

### 새로 통합할 가치가 있는 것 (모두 "별도 모듈", 외부 의존 없음)

1. **해부 규칙 검사기 `anatomy_check.py`**(새 모듈, fitloop 과 분리). 입력은 마스크에서 읽은 지표(예: 눈~코끝 길이 / 머리 길이, 주둥이 폭 / 두개골 폭, 관절 위치 후보). 출력은 PASS·FAIL·UNKNOWN. 규칙은 팩 JSON 에 둔다(하드코딩 금지). 규칙의 **출처**(수의 해부 자료·기준 도면 몇 장)와 **신뢰도**(가설/도면 확인)를 필드로 둔다.
2. **데포르메 의도와 해부 사실의 분리:** 규칙에 `kind: anatomy | design_intent` 를 두고, design_intent(3등신 큰 머리, 큰 눈)는 도면이 이기도록 해부 규칙 FAIL 을 경고로만 처리한다.
3. **비정상 변형 탐지:** fitloop 의 걸음별 메시 건전성(이미 있음)에 해부 비율 이탈 검사를 추가.
4. **리깅 단계:** 모델이 완성된 뒤 Rigger(4족·말·새 템플릿)를 후보로 시험. 모델링 파이프라인과는 분리.
5. 기준 동물 여러 마리를 섞는 PCA 아이디어(Morph)는 v0.2 이후 "체형 템플릿" 연구 과제로 보관.

### 통합하지 않는 것과 이유
- 사람 해부 MCP(Anatomy Engine): 대상 불일치, 좌표 없음, 데이터 미검수.
- 외부 MCP 3종: 폐루프 보정이 없어 대체 불가, 의존성·유지보수 부담만 증가(Blender AI MCP 는 중단).
- Morph·MuSkeMo 코드: 라이선스 없음 + 목적·버전 불일치.

### 도면 중심 흐름의 실현 가능성
`도면 + 해부학 지식 → 기본 골격·체형 → 메시 → 도면 비교 → 자동 보정 → 해부 제약 검사 → 출력`
- 지금 있는 것: 메시 → 도면 비교 → 자동 보정(fitloop, 합성 시험 PASS), 메시 건전성 검사.
- 없는 것: **"기본 골격·체형에서 외형 메시 생성"** 단계(외부 도구에도 없음), **해부 제약 검사**.
- 가능한 경로: 기본 메시는 지금처럼 사람이 만든 시작 메시(옛 머리 등)나 이전에 만든 고리 케이지를 쓰고, 해부학은 "검사 + 비율 목표" 로만 개입한다. 해부학이 형상을 생성하는 것은 현재 증거로는 불가능하다.

| C. 규칙 데이터 작성 | 들소(우제류) 머리 비율 몇 개. **출처 확인이 필요**(수의 해부 서적·Z-Anatomy 동물 자료·기준 도면). 확인 전에는 `신뢰도: 가설` | 사람 검토 필요 |
| D. 리깅 시험(선택) | Rigger 4족 템플릿을 별도 환경에서 시험 | 설치 승인 필요, 별도 |

## 6. 개발 계획에 추가할 작업과 충돌 여부

- **충돌 없음.** fitloop·selftest·SKILL 은 그대로이고, 위 A·B 는 별도 파일·선택 입력이다. 규칙이 없으면 동작이 지금과 같다.
- 추가 작업(우선순위는 기존 순서를 바꾸지 않고 뒤에 둔다): 들소 주둥이 실험(3단계, 승인 대기) → A·B(해부 규칙 검사기) → C(규칙 데이터, 출처 확인) → D(리깅, 승인 시).

## 8. 권장 통합 순서

1. (그대로) 들소 주둥이 실험은 승인 뒤. 해부학 때문에 앞당기지 않는다.
2. 해부 규칙 스키마(A·B)를 합성 도형으로 먼저 시험(해부 지식 없이 구조만).
3. 들소 규칙 데이터(C)를 출처와 함께 작성하고, 도면에서 측정한 비율과 교차 확인해 `가설 → 도면 확인` 으로만 승격.
4. 리깅(D)은 모델이 안정된 뒤 Rigger 를 격리 환경에서 시험(GPL 이므로 코드 포함 금지).
