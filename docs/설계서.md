S1·S2 범위 보강 (외부 검토 3차, 사용자 전달):
- 단계 이름을 바꾼다. **1단계 최소 하네스 → 2단계 합성 도형 자체 시험 → 3단계 들소 주둥이(별도 승인 뒤) → 4단계 여러 부위.** 1·2단계에서는 실제 크리처 도면을 쓰지 않는다.
- 합성 시험: Blender에서 정답 형상(타원체 + 코 돌기 등)을 만들고, 그 정면·옆 직교 렌더를 "목표 도면"으로 쓴다. 의도적으로 틀어진 형상(핸들을 알려진 양만큼 옮긴 것)에서 시작한다. 검증 항목은 좌표계 정렬, 측정 정확도, 핸들-메시 대응, 이동 방향·크기 계산, 반복에 따른 오차 감소, 대상 밖 보존, 체크포인트 복원, 재현성이다. **알려진 정답 이동량을 하네스가 되찾는지**(차이 ≤ 10%)도 확인한다.
- 반복마다 기록할 것: 수정 대상, 수정 전 오차, 사용한 핸들, 계산된 이동량, 수정 후 오차, 부작용 검사 결과, 체크포인트 경로.
- 금지: 새 MCP·대형 의존성 설치, 기존 파일 삭제·덮어쓰기, **들소 전용 좌표·하드코딩된 부위 규칙**(규칙은 팩 JSON에만 둔다), Blender 내장 기능으로 되는 변형의 재구현, 처음부터 모든 크리처용 범용 시스템, 시험 실패를 눈대중 수정으로 우회하는 것.
- 첫 성공 기준은 좋은 3D 모델이 아니다. **정답을 아는 단순 도형을 일부러 망가뜨렸을 때 하네스가 도면만으로 오차를 재고 자동으로 복구하는 것**이다. 이것이 서야 나중에 들소가 실패해도 원인이 도구인지, 도면 정보 부족인지, 형상 복잡성인지 가를 수 있다.

사용자가 찾아 준 두 저장소를 `gh api`로 열어 실제 코드를 읽었다.

| 저장소 | 사실 | 우리 문제에 대한 판단 |
|---|---|---|

| [MAX-786/claude-3d-harness](https://github.com/MAX-786/claude-3d-harness) MIT, 2026-09-18 생성, 2026-09-21 마지막 푸시, 별 7 | 위 스킬 묶음 등을 `library/`에 복사해 두고, 등록부·워크플로·MCP 서버 하나로 묶은 진입점. Blender 4.2+·`uv` 필요 | 관리 계층이다. 3일간 작업 후 멈춤. 형상 계산 기능은 없다 |

**채택:** cc-blender-skill의 **수리 대기열 형식**(단계·실패·측정 차이·제안 행동·통과 조건)을 우리 `measure` 출력 형식으로 쓴다(MIT, 출처 표기). 정투영 패널 정렬·스킬 문서 구조도 참고한다.
**우리가 더 하는 것:** 제안 행동을 LLM이 손으로 옮기지 않는다. `fit`·`snap`·`round` 같은 명령이 형상을 계산해 바꾼다. 형상 표현은 정면 판이 아니라 고리 케이지 부피다.
**비교 실험(선택, 사용자 승인 필요):** cc-blender-skill을 그대로 들소 머리에 돌려 같은 측정표로 비교할 수 있다. 이때 Blender 번들 Python에 opencv-python을 설치해야 한다. 예측: 정면 IoU는 높고, 옆·3/4는 낮다(정면 판 + 변위 구조라서). 이 예측이 틀리면 우리 설계를 다시 본다.

### 0-2. 설계 수정 (외부 검토 반영)

1. **정점 번호에 묶지 않는다. 이름 있는 제어 핸들에 묶는다.** `CTRL_코끝`(Hook 빈 객체 + 규칙으로 고른 정점 그룹), `LATTICE_주둥이`(부위 범위를 감싼 Lattice), `LOOP_주둥이앞`(규칙으로 고른 정점 그룹). 정점 그룹은 매번 규칙("옆 실루엣 4.4~4.8H 가장 앞 점에서 반경 r")으로 다시 고르므로, 메시를 다시 만들거나 세분해도 의미가 유지된다.
2. **변형은 Blender 내장 기능으로 한다.** Hook·Lattice·Laplacian Deform·비례 편집(5.2.1 존재 확인). numpy로 따로 짜지 않는다. 측정은 기존 `trace_iou.py` 방식(도면 패널 좌표·실루엣 래스터)을 그대로 쓴다.
3. **오차 계산과 수정 방향 계산을 나눈다.** 정면은 X·Z, 옆은 Y·Z만 안다. 핸들 목표 3D 위치 = 정면 X + 옆 Y + 두 뷰 Z(다르면 경고). 한 뷰에서만 보이는 랜드마크는 다른 축을 움직이지 않고 UNKNOWN으로 남긴다.
4. **장기:** 54종을 위해 머리·주둥이·목·뿔을 의미 있는 매개변수로 제어하는 모델 구조(고리 케이지 = 5절)가 필요하다. 다만 이것은 v0.0 주둥이 실험이 PASS한 뒤에 만든다.

### 0-3. v0.0 최소 실험: 들소 주둥이만 (이것을 먼저 한다)

- 대상: 옛 머리 `fixtures/bison_head/old_head_bison_bp.obj`를 H 좌표로 올린 것(실패한 그 모델).
- 측정(자동, 손 좌표 0): ① 코끝 = 옆 실루엣 극점 규칙, ② 주둥이 폭 = 정면 도면의 **어두운 코 영역** 너비(색 임계로 분리, 도면 값 약 0.29H)와 모델 코 그룹(`nose`) 너비.
- 수정(자동): `CTRL_코끝` Hook을 목표 3D 위치로 옮기고(감쇠 반경 규칙으로), `LATTICE_주둥이`를 X 방향으로 폭 비율만큼 조정한다. 적용 후 OBJ로 내보낸다.
- 비교: 수정 전후 코끝 오차·코 폭 오차·머리 띠 IoU(정면·옆), 정면·옆·3/4 렌더를 도면과 나란히.
- 통과: 코끝 오차 ≤ 0.05H, 코 폭 0.29±0.03H, 정면·옆 머리 띠 IoU가 수정 전보다 낮아지지 않음, 닫힘·좌우 대칭 유지.
- 보고: 재사용한 것(trace_iou 방식, Blender 내장 변형, cc-blender-skill 형식)과 새로 쓴 최소 코드(규칙 → 정점 그룹, 2뷰 → 3D 목표, 핸들 배치)의 경계.

#### 0-3 보강 (외부 검토 2차 반영, 2026-10-28)

목표는 하나다: **도면에서 자동 측정한 코끝·코 폭 오차가 Blender 메시의 실제 변형으로 이어지고, 반복 수정으로 줄어드는지 증명한다.** 새 모델 생성 알고리즘이나 전체 크리처 하네스는 만들지 않는다.

1. **폭 두 개를 나눈다.** ① 코 영역 폭 = 정면 도면의 어두운 코 영역 좌우 범위, ② 주둥이 외형 폭 = 같은 높이에서 주둥이 덩어리의 좌우 윤곽(얼굴 안쪽 경계라 색면 경계로 잰다. 못 재면 UNKNOWN). `0.29H`는 옛 머리 보고서의 "도면_코폭" 값인데 어느 폭인지 정의가 없다. 실험에서 두 값을 모두 다시 재고, 통과 조건 `0.29±0.03H`가 어느 것인지 결과 보고에 명시한다. 모델 쪽도 같은 두 폭을 잰다(코 그룹 `nose` 폭 / 같은 높이 메시 단면 폭).
2. **정점 재선택 검증.** 규칙으로 고른 정점 그룹마다 정점 수, 공간 범위(bbox), 옛 OBJ의 그룹 이름(`nose`·`head` 등) 구성비를 기록한다. 코끝 그룹이 `nose` 그룹 밖 정점을 절반 넘게 포함하면 FAIL.
3. **민감도 측정.** 각 핸들을 작은 양(예: 0.01H)만큼 축별로 움직여, 실루엣 지표(코끝 위치, 두 폭, 머리 띠 IoU)가 얼마나 변하는지 표로 남긴다(수치 야코비안). 이동량은 이 표로 계산한다. LLM이 추측하지 않는다.
4. **작게 반복한다.** 한 번에 오차 전부를 고치지 않는다. 걸음마다 남은 오차의 최대 50%까지만 옮기고 → 재측정 → 반복. 최대 10걸음. 걸음마다 오차표를 남긴다.
5. **부작용 검사.** 수정 대상이 아닌 머리 띠(두개골·목·귀·뿔 높이) 정면·옆 오차가 0.02H 넘게 나빠지면 FAIL. 아래턱이 따라 늘어나는지(턱끝 위치 변화)도 기록한다.
6. **메시 건전성.** 면 뒤집힘(법선 반전 수), 자기 교차(있으면 FAIL), 닫힘·좌우 대칭, 주둥이-머리 연결부 최소 단면 폭이 수정 전보다 20% 넘게 줄면 FAIL.
7. **3/4는 자동 합격시키지 않는다.** 정면·옆 수치가 통과해도 3/4 렌더는 메인 세션(그리고 사용자)이 눈으로 본 뒤 판정한다. 자동 판정란은 "3/4: 사람 검토 대기"로 둔다.
8. **보존.** 걸음마다 `.blend` 체크포인트, 오차표 JSON, 비교 렌더(정면·옆·3/4)를 `runs/v0.0/stepNN/`에 남긴다. 같은 입력으로 두 번 돌려 최종 정점 해시(또는 오차표)가 같은지 확인한다(결정론).

다음 단계(이 실험 PASS 뒤): 머리·목·몸통처럼 이어진 여러 부위를 동시에 고칠 때 제약이 충돌하는 문제를 검증한다. 주둥이 실험 하나의 성공으로 54종 자동 제작이 된다고 결론 내리지 않는다.

## 1. 원칙

1. **LLM은 좌표를 쓰지 않는다.** 명령에 들어가는 값은 이름(랜드마크·부위·고리 범위), 규칙(극점, 높이 범위), 상대값(둥글기 지수, 강도 0~1)뿐이다. 도면 위치는 도구가 도면에서 계산한다.
2. **모든 명령은 측정 보고를 돌려준다.** 그림보다 숫자가 먼저고, 그림은 요청할 때만 준다.
3. **같은 규칙을 도면과 모델에 똑같이 적용한다.** 예: "옆 실루엣에서 높이 4.4~4.8H 사이 가장 앞 점"이라는 규칙이 도면에서는 목표 위치를, 모델에서는 움직일 정점을 정한다. 대응 관계가 규칙에서 생긴다.
4. **단계 관문.** 큰 덩어리가 맞아야 세부로 넘어간다. 관문 판정은 PASS·FAIL·UNKNOWN·ERROR 넷뿐이다.
5. **결정론.** 같은 명령열이면 같은 메시와 같은 해시가 나온다. 모든 명령은 기록되고 되돌릴 수 있다.
6. **무료·로컬.** Blender 5.2 번들 Python + numpy만 쓴다. MCP, 새 설치, GPU, 학습 모델은 쓰지 않는다. 그림 렌더만 `blender -b`를 쓴다.

## 3. 좌표 규약

- 단위 H(머리 높이). 하네스 안 좌표: **X = 캐릭터 오른쪽 +, Y = 앞 +, Z = 위(발바닥선 0)**.
- 패널 변환은 `trace_meta.json`을 따른다: `가로 = x부호 × (px − 중심선_x) / px_per_H`, `h = (발바닥선_행 − py) / px_per_H`.
  - 정면 패널: X. 옆 패널: Y. 뒤 패널: X(부호 반대).
- 내보낼 때만 프로젝트 단위로 바꾼다(케라투라: Blender 길이 = H × 0.598, OBJ y-up·z 앞).

## 4. 참조 팩 (`pack.json`)

```json
{
  "name": "bison_head",
  "drawing": "drawing.npy",
  "panels": {"front": {...}, "side": {...}, "back": {...}},
  "profile": "profile.json",
  "silhouette": "silhouette.json",
  "roi": {"z": [4.25, 5.55]},
  "parts": {"주둥이": {"z": [4.35, 4.85], "y": [0.45, 1.1]}, "두개골": {...}, "목덜미": {...}},
  "landmarks": {
    "코끝":   {"rule": "extreme", "view": "side",  "dir": "+Y", "z": [4.4, 4.8]},
    "후두":   {"rule": "extreme", "view": "side",  "dir": "-Y", "z": [4.9, 5.2], "source": "core"},
    "턱끝":   {"rule": "extreme", "view": "side",  "dir": "-Z", "y": [0.5, 0.9]},
    "볼폭":   {"rule": "extreme", "view": "front", "dir": "+X", "z": [4.6, 4.9], "source": "core"},
    "눈":     {"rule": "manual",  "view": "front", "px": [300, 205], "conf": "추정"}
  }
}
```
- `profile`의 `*_core`(뿔·귀·꼬리 제외) 행이 몸통 윤곽 목표다. 0.05H 간격.
- 랜드마크 규칙 종류: `extreme`(실루엣 극점), `contour_at`(높이 z에서 윤곽 앞/뒤/바깥 끝), `manual`(픽셀 직접, 신뢰도 표시 필수, 겹침 그림으로 검수). **manual은 실루엣 밖 내부 특징(눈·코 폭)에만 쓴다.**
- 3D 랜드마크 = 정면 패널의 X·Z와 옆 패널의 Y·Z를 합친다. 두 패널 Z가 다르면 차이를 보고하고 평균을 쓴다(도면 불일치 경고).

## 5. 고리 케이지 (`cage.py`)

- 고리 R개(높이 z_i), 고리당 반쪽 점 M+2개(앞 중심 → 뒤 중심, 코사인 간격). 거울 대칭으로 전체 고리를 만든다. 위는 꼭짓점 하나로 닫고, 아래는 덮개로 닫는다(옵션 열림).
- 고리 i의 매개변수:
  - `z`: 높이
  - `yf`, `yb`: 앞끝·뒤끝 Y
  - `a`: 기준 반폭
  - `n`: 단면 초타원 지수(둥글기. 2 = 타원, 클수록 네모)
  - `w[k]`: 앞뒤 방향 K=9개 제어점의 폭 배수(기본 1). 주둥이처럼 앞쪽만 좁은 형태를 표현한다.
  - `cx`, `cy`: 중심 이동(머리 숙임 등)
- 정점 = 매개변수 위치 + **조각 오프셋** `d[i,j]`. 오프셋은 (고리, 점) 번호로 저장해서 매개변수를 바꿔 다시 만들어도 유지된다. 고리를 넣고 뺄 때는 보간한다.
- 고리 = 에지 루프이므로 리깅 루프 규칙(관절 근처 고리 2개 이상)을 고리 배치 제약으로 둘 수 있다.

## 6. 명령 (손)

모든 명령은: 현재 버전 읽기 → 적용 → 측정 → 새 버전 저장 → 짧은 보고(20줄 이하) 출력.

| 명령 | 하는 일 | 모델러의 동작 |
|---|---|---|
| `init --pack P --rings R --z a b` | profile core에서 고리를 자동 생성(반폭·앞끝·뒤끝 = 도면 값, n=2.5). **첫 블록아웃이 이미 정면·옆 윤곽에 맞는다** | 참조 위 블록아웃 |
| `fit --view front\|side\|back [--z a b] [--strength s]` | 그 높이 범위에서 고리의 a / yf / yb를 도면 윤곽 쪽으로 s만큼 옮긴다(이웃 고리로 부드럽게) | 에지 루프 스케일로 윤곽 맞추기 |
| `snap <랜드마크> [--falloff r]` | 같은 규칙으로 모델 정점을 찾아 도면 위치로 옮긴다. 주변은 매끈한 감쇠(코사인, 반경 r H)로 오프셋 | 비례 편집으로 점 끌기 |
| `round --z a b --n v` | 단면 지수를 바꾼다. 정면·옆 윤곽은 유지되고 3/4 부피만 바뀐다 | 덩어리 둥글리기 |
| `narrow --part 주둥이 --width v` 또는 `--from-landmark 코폭` | 부위 범위 안 고리의 앞쪽 폭 배수 w[k]를 조정한다 | 주둥이 좁히기 |
| `shift --z a b --dy v` / `--tilt deg` | 고리 중심 이동·기울이기 | 머리 숙이기 |
| `add_ring --z v` / `remove_ring --i k` | 고리 추가·삭제(오프셋 보간) | 루프 컷 |
| `smooth --z a b [--k s]` | 매개변수·오프셋 평활 | 스무스 |
| `undo` / `goto vNNN` / `log` | 되돌리기·버전 이동·기록 | Ctrl+Z |
| `measure [--full]` | 보고만 | 참조와 대조 |
| `show [--views front,side,back,q34]` | 겹침 PNG(도면 + 모델 외곽선 빨강, 오차 띠 색) | 뷰포트 확인 |
| `gate <단계>` | 관문 판정 | 다음 단계 진입 판단 |
| `export --obj out.obj [--project keratoura]` | 내보내기 | 저장 |

값 범위 제한: strength 0~1, falloff 0.05~0.6H, n 1.6~5, width 0.3~1.5. 범위를 벗어나면 명령을 거부한다(ERROR).

## 7. 측정 (눈)

`measure`가 내는 것(JSON 저장 + 요약 출력):
1. **높이 띠 오차** (0.05H, roi 안): 정면 반폭, 옆 앞끝·뒤끝, 뒤 반폭에 대해 모델 − 도면 값. 띠마다 부위 이름과 해당 고리 번호를 붙인다.
   예: `옆 앞끝 z4.55~4.65 모델 0.70 도면 1.01 (−0.31) 부위=주둥이 고리=7~8`
2. **랜드마크 오차**: 각 랜드마크의 3D 거리와 축별 차이.
3. **실루엣 IoU** (정면·옆·뒤, roi, core 기준): 모델은 매개변수에서 바로 투영해 다각형으로 만들고, 도면 core 다각형과 비교한다.
4. **3/4 부피 검사**: 띠마다 45° 투영 폭 / 상자 상한 `(정면폭+옆폭)/√2`의 비율. 타원 하한 비율 `√((정면폭²+옆폭²)/2)/상한`도 함께 보고한다. 목표 구간은 관문 설정값이다(가설, 아래 9절).
5. **메시 검사**: 닫힘, 자기 교차(인접 고리 간 반전), 좌우 대칭 오차, 삼각형 수.
6. **요약 최악 5개**: cc-blender-skill 수리 대기열 형식(`stage, failure, measured_delta, proposed_action, acceptance_gate`)으로, 오차가 큰 항목을 명령 추천과 함께 낸다. 예: `→ snap 코끝` / `fit --view side --z 4.5 4.7`. 추천은 규칙 기반이고, LLM은 따를지 정한다.

속도 목표: `measure` 1회 1초 이하(래스터 없이 고리 매개변수에서 해석적으로 계산). `show`만 래스터를 쓴다.

```

  log.jsonl(명령·인자·측정 요약·해시)  report_vNNN.json  show_vNNN_*.png  export/
```

- `undo`는 포인터만 옮긴다. 기록은 지우지 않는다.

## 9. 관문 (기본값, `gates.json`에서 바꿀 수 있음)

| 단계 | 조건 | 비고 |
|---|---|---|
| G1 블록아웃 | 정면·옆 IoU ≥ 0.90, 띠 오차 최대 ≤ 0.10H, 닫힘 | init 직후 대부분 통과해야 정상 |
| G2 랜드마크 | 코끝·후두·턱끝 오차 ≤ 0.05H, manual 랜드마크 ≤ 0.08H | |
| G3 부피 | 3/4 비율이 상자 상한의 0.80~0.92 (모든 roi 띠) | **가설.** 들소 3/4 도면을 받으면 보정 |
| G4 마감 | 정면·옆 IoU ≥ 0.95, 띠 오차 최대 ≤ 0.05H, 대칭 오차 0, 삼각형 ≤ 예산 | |

같은 관문에서 명령 12개를 써도 PASS가 안 나오면 멈추고 남은 오차를 보고한다(사람 판단).

## 10. LLM 작업 규칙 (`SKILL.md`로 배포)

1. `init` → `gate G1` → `measure` 최악 5개를 보고, 명령 하나를 고르고, 보고를 읽고, 반복한다.
2. 좌표 숫자를 만들지 않는다. 명령 인자는 이름·범위·상대값만 쓴다.
3. 구조적으로 안 맞으면(예: 주둥이가 고리 하나로 표현 불가) `add_ring`이나 부위 분리를 결정한다. 이것이 LLM의 몫이다.
4. 그림(`show`)은 관문 통과 직후와 사람에게 보여 줄 때만 본다.
5. 뿔·귀는 별도 부품이다(이 버전 범위 밖. 다음 버전에서 "관 고리 부품"으로 확장).
