# 설계: 옳은 형태를 판단하는 능력(도면 오류를 무시할 근거) (2026-10-29)

사용자 지적: "이전에 소의 뿔이 gpt 로 인해서 잘못 그려진 적이 있습니다. 인간은 무시하고 그리면 되겠지만 인공지능은 그걸 무시해야 하는지 판단할 근거가 필요해 보였습니다. 정확한 트레이싱만이 중요한 게 아니라 옳은 형태를 판단하고 추론하는 능력도 필요합니다."
실제 사례: 들소 옆 그림의 반대편 뿔이 비켜 그려져 옆 트레이스가 넓어졌고, 헐이 판자가 됐다(수정_기록 19). 그때는 규칙 하나(`pair_side_no_claim`)로 막았다가 정사영 도면을 해쳐(옆 뿔 0.972→0.920) LLM 결정으로 돌렸다. **근거 없이 무시하면 정상 도면을 해치고, 근거 없이 따르면 오류를 모델에 옮긴다.**

## 1. 조사

| 근거 종류 | 연구 | 배울 점 |
|---|---|---|
| 다른 뷰가 투표 | RobustVGGT(뷰마다 공유 형상과의 일치 점수, 한 문턱으로 어긋난 뷰 버림, [arXiv 2512.04012](https://arxiv.org/pdf/2512.04012)), MVGSR(이웃 뷰와 특징 유사도로 이상치, [arXiv 2503.08093](https://arxiv.org/pdf/2503.08093)), 뷰 일치의 정의(모든 뷰를 한 3D 로 비출 수 있으면 일치, [arXiv 2608.09110](https://arxiv.org/pdf/2608.09110)) | 한 뷰에만 있는 모양은 의심. **뷰끼리의 합의가 첫 근거** |
| 규칙성과 충실함의 저울 | True2Form(대칭·평행 같은 규칙성을 **골라서** 적용, 손그림 선과의 충실함과 저울질, 사람 지각 실험과 일치, [프로젝트](https://www.cs.ubc.ca/labs/imager/tr/2014/True2Form/index.htm)), 대칭 기반 개념 스케치 복원(가장 대칭적이고 잘 이어진 해를 고름, [기록](https://science.ulysseus.eu/records/001ph-zxp29)), 설계 의도 = 기하 관계, 적응형 허용치로 가짜 대칭을 줄임([Li 외](https://www.cs.princeton.edu/courses/archive/spring11/cos598A/pdfs/Li10.pdf)), 고친 결과가 아니라 원래 그림에서 제약을 찾음([Pu·Ramani](https://www.cs.hmc.edu/courses/2008/spring/cs182-pbc/papers/Pu2007.pdf)) | 고치기는 **"그림에서 얼마나 벗어나나" 대 "규칙성 근거가 얼마나 강한가"** 의 저울. 약하면 그림을 따른다 |
| 형태 사전의 위험 | AdversarialAnatomyBench(VLM 22개, 흔한 해부 74% → 드문 변이 29%, 키워도 안 고쳐짐, [arXiv 2512.04238](https://arxiv.org/pdf/2512.04238)) | VLM 은 '흔한 몸'을 믿는다. 환상 크리처의 **의도된 특이함을 오류로 고칠 위험**. 사전만으로는 고치지 않는다 |
| 생성 그림의 흠 찾기 | INSIGHT(생성 그림의 생물학적으로 말이 안 되는 흠을 VLM 으로 추론, [arXiv 2511.22351](https://arxiv.org/pdf/2511.22351)), 동물 해부 그럴듯함 규칙 점수(부위 규칙, 큰 머리 같은 위반, [arXiv 2511.15204](https://arxiv.org/pdf/2511.15204)), 생성 의학 삽화의 해부 오류 조사([PRS GO 2026](https://www.ovid.com/jnls/prsgo/fulltext/10.1097/gox.0000000000007676~a-i-naccurate-anatomy-prevalence-of-artificial)) | AI 도면은 오류가 흔하다는 전제. 흠 후보는 **규칙(부위 관계)** 로 먼저, VLM 은 설명용 |
| 참고 사진으로 확인 | ORIG(웹에서 그림·글 증거를 모아 사실에 맞게, [arXiv 2510.22521](https://papers.cool/arxiv/2510.22521)), 종·부위 오류 분류(종이 틀림 / 색·무늬·부위가 틀림, [arXiv 2609.01375](https://arxiv.org/pdf/2609.01375)), 참고 그림과 비교해 부위 찾기 RAU([arXiv 2509.22404](https://arxiv.org/abs/2509.22404)) | 실제 동물(들소)이면 **참고 사진**이 근거가 될 수 있다. 환상 크리처면 근거가 아니다 |
| 그럴듯함을 점수로 | APAP(2D 확산 모델로 변형의 그럴듯함을 점수화, [CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Yoo_As-Plausible-As-Possible_Plausibility-Aware_Mesh_Deformation_Using_2D_Diffusion_Priors_CVPR_2024_paper.html)), ARTIC3D(잡음 많은 웹 사진에서 관절 동물 형태) | GPU 학습형이라 지금은 참고. 나중에 검사기 하나로 |

## 2. 설계: '형태 판단' 단계

**순서 원칙(사용자 지적):** 먼저 그림 그대로의 정확한 트레이싱을 만들어 `원본 트레이스`로 보관하고, 형태 판단은 그 위의 **다듬기 층**이다. 바꾼 부분만 차이로 기록하고, 근거가 없으면 바꾸지 않으며, 언제든 원본으로 되돌릴 수 있다. 트레이싱이 틀리면 다듬기가 아니라 트레이싱을 먼저 고친다.

트레이스 뒤, 3D 전에 둔다. 출력은 **의심 목록**과 **결정**이며, 결정은 지금의 `decide` 기록과 같은 형식(부위·종류·결정·근거).

### 2.1 근거 다섯(각각 0~1 점수, 어디서 나왔는지 기록)
| 근거 | 재는 법 | 비고 |
|---|---|---|
| E1 뷰 합의 | 정면·옆·뒤의 높이·폭·위치가 한 3D 로 설명되나(지금의 높이 검사, 재투영 잔차, 그림 모순 진단) | 가장 강한 근거 |
| E2 대칭 | 정면·뒤 좌우 거울 일치, 좌우 짝 부위(뿔·귀)끼리 모양 일치 | 짝 부위가 한쪽만 이상하면 의심 |
| E3 부위 관계 규칙 | 붙는 자리(뿔은 머리 위옆), 크기 비율(귀가 머리보다 클 수 없음 같은 넓은 한도), 연결(떠 있는 부위 없음) | 부위 그래프(R2)의 맞물림 규칙과 같은 것 |
| E4 형태 사전 | LLM 지식(객관식 질문, 두 모델 가족 합의) + 실제 동물이면 참고 사진(사용자가 준 것 또는 승인된 검색) | **단독으로는 고치지 않음**(위험 근거: 드문 변이 29%) |
| E5 도면 출처 신뢰 | AI 생성 도면이면 낮게, 사람이 그린 정식 시트면 높게(사양에 적음) | 문턱만 바꾼다 |

### 2.2 결정 규칙(True2Form 식 저울)
- 의심 후보는 **E1 또는 E2 가 어긋날 때만** 만든다. E3·E4 만으로는 후보를 만들지 않고 '참고 표시'만 한다(의도된 디자인 보호).
- 후보마다 고친 모양 둘 이상을 만든다: (가) 그림 그대로 (나) 다른 뷰를 따름 (다) 대칭 짝을 거울로 옮김. 각 안에 대해 '그림에서 벗어난 넓이'와 '맞춰진 근거 수'를 잰다.
- **독립 근거 둘 이상이 같은 안을 가리키고, 두 모델 가족(Claude·Codex)의 판단이 일치할 때만** 그 안으로 고친다. 아니면 그림을 따르고 UNKNOWN 으로 남겨 사람이 볼 목록에 올린다.
- 고친 곳은 '가정'으로 표시하고(지금의 보라색), 그림에서 벗어난 넓이를 보고한다.

### 2.3 들소 뿔 사례에 대입
- E1: 옆 뿔이 정면에서 잰 뿔 폭보다 넓다(옆 트레이스 폭 vs 정면에서 기대되는 깊이).
- E2: 정면의 좌우 뿔은 대칭인데, 옆에서 보이는 '반대편 뿔' 조각은 정면 대칭으로 설명되는 자리가 아니다.
- E3: 반대편 뿔은 옆에서 머리 뒤로 가려져야 하는 자리.
- → 독립 근거 셋이 '옆의 그 조각은 반대편 뿔, 이 부위가 아님'을 가리킴 → 덧붙이지 않음(지금은 사람이 시킨 `claim_off` 결정을 근거와 함께 자동으로).

## 3. 검증 계획(돌리기 전에 정한 기준)
1. **오류 주입 합성 벤치마크**: 정답 3D 에서 그린 합성 도면에 오류를 일부러 넣는다. (a) 한 뷰에서만 뿔을 비켜 그림 (b) 한 뷰에서만 귀를 빼먹음 (c) 정면 좌우 뿔 크기를 다르게 (d) 옆 턱을 아래로 늘림. 그리고 **의도된 특이함**: (e) 모든 뷰에서 일관되게 비대칭인 뿔(환상 크리처).
2. 측정: 오류를 고친 비율(재현율), 고친 것 중 진짜 오류 비율(정밀도), 의도된 특이함을 잘못 고친 비율(오교정률), 3D 재투영 IoU 와 정답 부피 IoU.
3. 채택 기준: 정밀도 ≥ 0.9, 오교정률 ≤ 0.05, 재현율 ≥ 0.6, 오류 없는 기존 벤치마크(68~79)에서 하락 없음. 정밀도를 재현율보다 앞에 둔다(틀리게 고치는 것이 못 고치는 것보다 나쁘다).
4. 실제 도면: 들소(반대편 뿔), 새 머리(정면에만 있는 가시 볏, 부리 높이 차 38px)에서 의심 목록이 사람이 보기에 맞는지 그림으로 확인.

## 4. 로드맵 자리
설계_LLM_3D모델러 의 R2(부위 그래프) 다음, R4(검사기) 와 함께: **R2.5 형태 판단**. 부위 그래프가 있어야 E3(부위 관계 규칙)을 쓸 수 있고, 형태 판단이 있어야 R4 검사기가 '그림대로'와 '옳은 형태'를 구분한다.

## 5. 못 찾은 것(UNKNOWN)
- 손그림·생성 그림의 **뷰 사이 오류**를 직접 다룬 벤치마크(사진 쪽만 있음).
- 동물 해부 그럴듯함을 3D 메시에서 CPU 로 재는 공개 도구.
- True2Form 의 정확한 저울 식(본문 필요).

## 6. 의도 파악 루프(피아식별을 잘게 쪼개서)

사용자 지적: "AI 가 그림을 보고 피아식별을 하는 것 같던데, 잘게 쪼개 분석하면서 의도 파악하는 루프가 들어가야 하지 않나요?"
그림을 볼 때 AI 가 실제로 하는 일은 영역마다 **"이건 이 크리처의 이 부위인가, 반대편 짝인가, 옆 그림·배경인가, 그림 오류인가, 그림자·무늬인가"** 를 가리는 것이다. 한 번에 통째로 물으면 흔들린다(재질 묶음 통째 질문 0.81~0.85, 한 질문으로 쪼개자 귀 0.787→0.930).

근거 연구: DeepEyes(모델이 스스로 영역을 골라 확대해 다시 보며 추론, 세부 인식·맞히기 향상, [arXiv 2505.14362](https://arxiv.org/abs/2505.14362v2)), VLM-R³(언제 더 볼지·어디를 볼지·본 것을 추론에 넣기, [arXiv 2505.16192](https://arxiv.org/abs/2505.16192v1)), Chain-of-Focus(적응형 확대). 주의: 확대를 거듭하면 느려진다([arXiv 2601.02918](https://arxiv.org/abs/2601.02918)) → 질문 수 한도.

### 6.1 루프
1. **쪼개기(도구)**: 그림을 작은 조각으로 나누고 번호(색 군집의 연결 조각, 톤 조각, 윤곽 조각). 지금의 교정 후보·군집 번호 그림과 같은 틀.
2. **피아식별 질문(LLM, 조각마다 객관식)**: {이 부위 / 다른 부위(이름) / 반대편 짝 / 배경·옆 그림 / 그림자·무늬 / 그림 오류 / 모르겠음}. 현재 답은 보여 주지 않는다(L13).
3. **증거 모으기(도구가 그림을 만들어 줌)**: 그 조각의 **확대 그림**, 다른 뷰에서 **같은 높이 띠**, 정면·뒤의 **좌우 거울 자리**, (실제 동물이면) 참고 사진.
4. **가설 → 예측 → 측정**: 예) "반대편 뿔이라면 정면 대칭 자리에 짝이 있고, 옆에서는 머리 뒤에 가려진 자리여야 한다" → 도구가 재서 맞으면 근거 +1, 틀리면 가설 버림. LLM 은 가설과 예측만 말하고, 맞는지는 도구가 잰다.
5. **합의**: 독립 근거 둘 이상 + 두 모델 가족(Claude·Codex) 같은 답 → 확정. 엇갈리면 조각을 **더 잘게** 나눠 다시(최대 2단), 그래도 엇갈리면 UNKNOWN 으로 그림을 따르고 사람 목록에.
6. **멈춤**: 모든 조각이 확정·UNKNOWN 이 되거나 질문 수 한도(도면당, 크레딧 관리).
7. **기록**: 조각마다 (답, 근거, 확대 그림 경로, 두 가족 답)을 결정 기록에. 같은 실수가 다시 나오면 교훈으로.

### 6.2 하네스에 들어갈 도구(좌표를 받지 않음)
- `inspect(조각 번호)` → 확대 그림, 다른 뷰 같은 높이 띠, 거울 자리 그림, 잰 값(넓이·높이 범위·짝 일치도).
- `ask(조각 번호, 질문 종류)` → 두 가족에게 같은 질문(보기 순서 반대), 답과 일치 여부.
- `test(조각 번호, 가설)` → 가설이 예측하는 측정(짝 존재, 가려짐, 높이 일치)을 도구가 재서 참·거짓.
- `resolve()` → 합의 규칙 적용, 결정 기록에 쓰기.

### 6.3 검증(돌리기 전에 정한 기준)
- 앞 3절의 오류 주입 벤치마크에 **옆 그림 조각·라벨이 끼어드는 장면**(새 머리 도면처럼)을 더한다.
- 측정: 조각 피아식별 정확도, 확정 비율, UNKNOWN 비율, 질문 수.
- 채택 기준: 확정한 조각의 정확도 ≥ 0.95, 확정 비율 ≥ 0.7, 오류 없는 도면에서 트레이스 IoU 하락 없음, 도면당 질문 수 ≤ 40.
