## A. 핵심 결론

**가장 큰 실패 원인은 LLM의 공간 추론 한계가 아니라 "측정과 조형이 끊긴 절차"다.** 도면 실루엣을 픽셀 단위로 재는 도구(`trace_sil.py`)와 모델 실루엣을 도면 위에 겹쳐 IoU를 내는 도구(`trace_iou.py`)는 이미 있고 실제로 돈다. 그런데 **조형 스크립트(`bison_head_bp.py`·`bison_upper_bp.py`·`bison_body.py`) 중 어느 것도 그 측정 JSON을 읽지 않는다**(코드로 확인: `grep`에서 트레이싱 JSON을 읽는 파일은 `trace_*`·`anat_*`뿐). 머리의 높이별 단면 21줄(`LEVELS`)은 LLM이 도면을 눈으로 보고 손으로 적은 숫자이고, 그 숫자를 측정값에 맞춰 푸는 최적화는 없다. 그 결과 3번의 수정 뒤에도 코끝이 도면보다 0.31H 짧고(실루엣 스캔 측정값) 주둥이·목·승모가 "병 모양"으로 단순화됐다.

**권장 솔루션: 하이브리드(C안) — "고리 케이지(loft) + 수치 최적화 + LLM은 구조 판단만".**
- 정점 좌표는 사람이나 LLM이 적지 않는다. 높이별 고리(ring)의 폭·앞뒤·단면 지수(초타원 n)를 **정면·옆·뒤 실루엣과 도면의 색면(셀 셰이딩 명도 3단)에 맞춰 수치 최적화**로 푼다.
- LLM은 (1) 부위 분할(어느 고리가 주둥이·두개골·목인지), (2) 랜드마크 선택, (3) 잔차 진단과 구조 수정 결정(예: "주둥이를 별도 덩어리로 분리"), (4) 분할선·토폴로지 규칙만 맡는다.
- 기존 코드 재사용: `trace_sil.py`(실루엣), `trace_iou.py`(측정기, 래스터라이저 포함), `bison_head_bp.py`의 반쪽 케이지→Mirror→닫힌 메시 골격, `kera_bl.py`의 `loft`·렌더 보조.
- 새로 필요한 것은 둘뿐: **(a) 측정값을 고리 파라미터로 바꾸는 솔버(numpy, CPU, LLM 호출 0회), (b) 색면 분할기(도면의 평평한 색면 = 3D 면 단서)**. 외부 MCP·학습 모델·GPU는 필요 없다. Blender 5.2.1 내장 기능(`grease_pencil.trace_image`, Shrinkwrap, Voxel/QuadriFlow Remesh)은 실행 확인했다.

학계 근거: 정면·측면 직교 캐릭터 도면에서 스윕 스플라인으로 베이스 메시를 만들고 주석으로 재최적화하는 방식이 이미 발표돼 있다(Huang·Xie·Fukusato, IWAIT 2022, C-2). 공개 코드는 찾지 못해 재구현이 필요하다. 바로 쓸 수 있는 기성 도구 중에는 이 일을 하는 것이 없다(C, C-2).

왜 이것인가: 세 가지 실험 사실 때문이다. ① 실루엣 측정은 이미 0.98~0.99 재현성으로 된다(기존 보고서 PASS). ② 세 직교 실루엣만의 visual hull은 3/4 시점에서 상자가 된다(이 세션 실행 확인: h=4.8에서 3/4 폭 2.07H = 상자 공식값 2.07, 타원이면 1.47). 그래서 "부피 복원"에는 단면 형태 사전지식(초타원)이 필수인데, 그 사전지식은 기존 머리 코드에 이미 있다. ③ 손으로 적은 파라미터 + 렌더 눈 확인 3회로는 0.31H 오차를 못 잡았다(기존 보고서 수치). 즉 부족한 것은 "표현력"이 아니라 "맞추는 절차"다.

**코드로 확인된 문제**
- 머리 `LEVELS` 정면 반폭 최대 0.315H(눈 높이), 도면 얼굴 폭 0.62H → 수치는 맞췄지만 코 폭 0.19H(도면 0.29H), 주둥이 블록 앞 돌출 없음. 같은 지수 n=2.8을 모든 높이에 써서 주둥이(네모)와 두개골(둥금)이 같은 둥글기.
- 승모·목: 머리 OBJ 안에 "목 덩어리"를 넣고 상체 혹에 묻히게 하는 방식 → 머리와 상체 사이 경계가 조립 위치에 민감, 승모근은 상체 담당·머리 담당 사이 책임 공백.
- 내부 형태 지표 없음: IoU 0.9여도 "삼각근·대흉근·주둥이 면 경계는 못 본다"고 보고서 스스로 적음.
- 도면의 **평평한 색면(셀 셰이딩 명도 3단)**은 3D 면의 방향 정보인데 어느 코드도 쓰지 않음(색면 분할 코드 없음).

**추정 원인(코드로 확정 못 함)**
- LLM이 도면을 보고 픽셀을 읽는 오차: 보고서 자인 ±3~6px(0.02~0.04H). 코끝 0.31H 오차는 이보다 10배 커서 "읽기 오차"가 아니라 **머리 기준 좌표계(눈 면 z=0, 턱 y=0)와 몸 기준 좌표계(발바닥·hip) 변환 과정의 누락**으로 추정.
- Eevee 렌더 3~6분 → 반복 횟수가 적었다(3회).

결론: **MCP와 알고리즘을 혼동하지 말 것.** Blender MCP·Agent Studio·OpenTopos·LL3M은 "LLM이 Blender를 조종하는 껍데기"이고 우리가 이미 가진 `blender -b -P` 방식과 같다. 3D 모델링 문제 자체를 푸는 기성 오픈소스 중 "정면+측면 도면 → 편집 가능 유기 메시"를 바로 해 주는 것은 **없다**. 가장 가까운 것은 visual hull(상자 문제)과 Monster Mash(측면 버림)뿐이다. 따라서 기존 부품의 조합이 답이다.

### C-2. 보강 조사 (2026-10-28 2차, 메인이 직접 웹 확인)

**같은 문제를 푼 선행 연구가 있다. 우리 권장안과 같은 방향이다.**

**Blender 애드온 (도면 → 메시)**
- 자동으로 정면·측면에서 메시를 만드는 애드온은 찾지 못했다.
- FSX3D Blueprint Tool(Superhive, 유료): 여러 뷰가 든 한 장의 도면에서 윤곽을 뽑아 거친 기본 부피를 만든다. 대상은 탈것이고 결과는 시작용 로우폴리라고 소개한다. 버전 호환과 품질은 확인 못 함.
- Blueprint Importer, Multi-View Reference Manager: 그림을 배치만 한다. 형상은 만들지 않는다.
- ReferenceMesh: 사람이 선택 도구로 영역을 따라 그려야 형상이 된다.

**Blender Agent Studio 재확인 (docs/reference-modeling.md 읽음)**
- 한 번 호출에 참조 이미지 **1장**만 받는다.
- 카메라는 사람이 맞춘다.
- 마스크를 주면 IoU, 누락·초과 픽셀, 랜드마크(최대 32개) 오차를 낸다.
- **자동 최적화는 없다.** 문서가 적은 반복은 에이전트가 소스를 고쳐 다시 부르는 수동 반복이다.
- 즉 우리 `trace_iou.py`와 같은 단계까지만 한다. 지금 실패한 지점(측정 → 조형 연결)을 풀어 주지 않는다.

**미분 렌더링 CPU 가능성 (Mitsuba 3)**
- `llvm_ad_rgb` 변형이 CPU 역렌더링용으로 기본 포함된다(PyPI 설명).
- 공식 형상 최적화 튜토리얼은 정점 기울기가 가시성 경계 정점에만 생겨 메시가 엉킨다고 경고한다. 해결책으로 "large steps"(잠재 변수 최적화)를 쓴다.
- CPU 실루엣 피팅 속도는 확인 못 함(UNKNOWN).
- 판단: 쓸 수는 있다. 하지만 우리 형상은 변수 ~150개의 고리 케이지라 미분 렌더링 없이 해석적 잔차로 충분하다. 큰 의존성을 들일 이유가 약하다.

**Image-to-CAD**
- CAD-Coder(arXiv 2505.14646): 이미지에서 CadQuery 코드를 만드는 공개 비전-언어 모델이다. 13B 모델이라 GPU가 필요하다.
- BenchCAD 계열 보고: 최신 모델도 겉모양은 잡지만 충실한 파라메트릭 프로그램은 자주 놓친다(집계 사이트에서만 봄, 원문 미확인).
- 대상이 기계 부품(돌출·필렛·구멍)이다. 근육·털 덩어리 크리처에는 표현 단위가 맞지 않는다(가설 E 지지).

### C-4. "AI가 숙련 모델러처럼 일하는 도구"가 오픈소스로 있는가 (2026-10-28 3차)

결론: **완성품은 없다. 부품은 있다.** 모델러에게 있고 AI에게 없는 여섯 가지 기준으로 대조했다.

가설 판정
- **A(트레이싱 먼저)**: 부분 참. 외곽 실루엣 트레이싱은 이미 유효(PASS). 그러나 "내부 선 트레이싱"은 답이 아니고 **색면 분할**이 답이다(도면이 셀 셰이딩이라 선이 아니라 면으로 정보가 있음). 반자동(LLM이 면에 이름 붙이고 사람이 승인)이 효율적.
- **B(정면·측면으로 부피 복원)**: 실루엣만으로는 **반증됨**(상자형 실측). 단면 사전지식(초타원 지수, 높이별로 다르게) 또는 3/4 도면이 있어야 한다. 3/4 도면이 없는 종족은 **명도 3단 색면의 폭 비율**로 지수를 추정하는 것을 제안(검증 전, 가설).
- **C(최적화 > LLM 직접 정점)**: 참. 증거: 측정기가 있는데도 손으로 적은 파라미터로 3회 실패. LLM이 직접 코드를 쓰는 편이 나은 경우는 **구조적 결정**(부품 분리, 분할선, 토폴로지, 앵커)뿐.
- **D(렌더 피드백 반복)**: 그림만으로는 부족(실증). 정량 지표 필요하되 IoU 단독은 "숫자만 좋고 3D 나쁨"에 취약(상자형 hull이 IoU 1.0인 반례를 이 세션에서 만들 수 있음). 대응: **3/4 폭 검사**(상자 공식값과 타원 공식값 사이에 있어야 함)와 **색면 명도 일치율**을 함께 본다.
- **E(CAD 부적합)**: 참이지만 "로프트"는 CAD 기법이면서도 생물에 잘 맞는다(척추·팔다리·주둥이 모두 관 모양). 털·갈기는 실루엣 톱니 부품으로 분리.

## E. 최종 권장 아키텍처 (데이터 흐름)

```
도면(정면·옆·뒤 webp)
 │ 1 trace_sil.py (기존)            → 실루엣 폴리곤·높이별 윤곽 profile.json
 │ 2 색면 분할기 (신규, numpy)       → 색면 JSON: 영역 id·색·명도 단(밝/중/어둠)·픽셀·이웃
 │ 3 LLM 구조 판단 (호출 1~3회)      → 부위 표: 각 색면·높이 구간에 부위 이름, 부품 분리(뿔·귀·갈기), 고리 수·앵커·분할선
 │ 4 초기 케이지 (기존 LEVELS 를 초기값으로, 또는 profile.json 에서 자동) 
 │ 5 솔버 (신규, numpy, LLM 0회)     : 변수 = 고리별 (폭·앞z·뒤z·지수 n·중심 x,z) → 잔차 = 정면/옆/뒤 실루엣 IoU + 높이띠 폭 차 + 색면 명도 일치(소프트웨어 법선 렌더) + 매끄러움 벌점
 │ 6 trace_iou.py (기존) 측정        → PASS/FAIL 표, 3/4 폭 상자 검사
 │ 7 LLM 잔차 진단 (호출 1~2회)      → 구조 수정(고리 추가·부품 분리) 후 5로 되돌아감, 최대 3회
 │ 8 Blender 조립 (bison_head_bp 골격): Mirror·닫힘·좌우 검사 → OBJ + 앵커 JSON + 케이지 곡선(.blend, 사람이 제어점 수정 가능)
 └ 9 Godot 부품 교체 시험(기존 body_rig_test)
```
- 사람 개입 지점: 3(부위 표 승인), 7(구조 수정 승인), 8(.blend에서 제어점 손질 → 다시 5 실행 가능).
- 리깅: 고리 = 에지 루프이므로 관절 루프 규칙(절차서 6단계)을 고리 배치 제약으로 솔버에 넣는다.
- 54종 확장: 종족별로 바뀌는 것은 도면과 3의 부위 표뿐. 솔버·측정기는 공용.

## I. 최종 판단

**"현재의 Claude Code + Blender 환경에서 별도 3D 생성 AI 없이, 정면·측면 도면 기반으로 캐주얼 크리처를 충분한 품질로 만들려면 무엇을 바꿔야 하는가?"**

1. **LLM이 좌표를 적는 일을 금지한다.** 좌표·폭·지수는 솔버가 측정값에서 푼다. LLM은 부위 표·구조 수정·검수만.
2. **측정기를 조형 앞에 둔다.** `trace_sil.py`/`trace_iou.py`를 "끝나고 재는 것"에서 "만드는 동안 잔차 함수"로 옮긴다. 통과 기준을 숫자로 둔다(G-7).
3. **도면의 색면을 데이터로 쓴다.** 실루엣은 이미 쓰고 있다. 빠진 것은 내부 형태이고, 셀 셰이딩 도면은 그것을 색면으로 준다.
4. **3/4를 숫자로 지킨다.** 3/4 도면이 없으면 상자·타원 공식 사이 검사로, 있으면 네 번째 잔차로.
5. **새 도구·MCP·GPU·학습 모델은 추가하지 않는다.** 필요한 설치는 선택 사항인 scipy 하나.

바꾸지 않아도 되는 것: Blender 헤드리스 방식, 케이지 로프트 + Mirror 골격, 부품(뿔·귀) 분리, OBJ+앵커 JSON 조립, Godot 교체 시험.

이 보고서는 연구·설계 결과이며 구현은 시작하지 않았다. 다음 단계는 G의 최소 실험(단계 2·5가 신규 코드)이며, 사용자 승인 뒤 한 builder에 묶어 맡기는 것을 권한다.

---

부록: 이 세션의 실험 기록
- `chk.py`(Blender 5.2.1 기능 확인): `grease_pencil.trace_image`, `voxel_remesh`, `quadriflow_remesh`, SHRINKWRAP·LATTICE·SKIN·REMESH 수정자 존재. potrace 모듈 없음(내장 C 구현으로 추정). numpy만 있고 scipy·cv2·PIL·skimage·trimesh·torch 없음.
- `hull.py`(세 실루엣 보셀 카빙, 0.01H 보셀, 머리 구간): 5.72M 보셀 중 1.68M 채움, 0.43초. h=4.6/4.8/5.0/5.2에서 3/4 폭 1.96/2.07/1.83/1.90H = 상자 공식값과 일치(타원값 1.43/1.47/1.30/1.39). → 실루엣만의 visual hull은 3/4에서 상자.
- 로컬 GPU: GTX 750 Ti 2GB → 학습 기반·미분 렌더링 경로는 로컬에서 비현실적.
