# 자유 조사 (2026-10-29)

사용자 요청: "필요한 논문을 내가 판단한게 병목이었을 수 있어. 너가 자유판단해서 조사해봐".
범위는 하네스 전체(도면 → 트레이싱 → 3D → 검사 → 리깅)에서 우리가 손으로 만들었거나 막힌 곳마다 기존 연구가 있는지로 잡았다.
아래 "적용"은 모두 가설이다. 벤치마크(합성 도면, 새 씨앗) PASS 전에는 기본값으로 넣지 않는다.

## 1. 가장 직접 관련된 연구

**3D Character Reconstruction from Hand-drawn Model Sheets** (Yoon·Jang·Hwang·Lee, POSTECH, Eurographics 2026, CGF 45(2)).
- 문제 설정이 우리와 같다: 손그림 모델 시트는 뷰끼리 서로 맞지 않아서, 어떤 하나의 형상도 모든 뷰에 맞을 수 없다.
- 해법: (1) 뷰 불일치를 줄이도록 형상을 최적화하고, (2) 남는 대응 오차는 뷰마다 변형 가능한 픽셀별 카메라 광선으로 흡수한다. (3) 그림을 뷰 의존 선, 뷰 독립 평면색, 세부 무늬(decal) 세 층으로 나눈다.
- 구현: TRELLIS(학습 3D 생성 모델)로 초기 메시, nvdiffrast, APAP 변형. RTX 4090에서 시험. 우리 제약(GPU·학습 모델 금지)으로는 그대로 쓸 수 없다.
- 우리에게 주는 것(가설):
  - 지금은 정면을 기준(master='front')으로 두고 다른 뷰를 맞춘다. 이 논문은 "모든 뷰를 존중하되, 뷰마다 작은 2D 변형을 허용하고 그 잔차를 보고"한다. 우리 방식으로 옮기면: 헐을 만들기 전에 각 뷰 실루엣에 작은 변형(높이 배율·이동)을 허용하고, 그 크기를 G 관문 보고에 남긴다. 반증 조건: 변형 허용 후 합성 벤치마크(일부러 뷰를 어긋나게 만든 변형)에서 결합 IoU가 오르지 않으면 기각.
  - 세부 무늬는 형상이 아니다. 눈 무늬·반점 같은 것은 트레이싱 부위에서 빼고 텍스처로 보낸다. 지금 트레이서에는 이 구분이 없다.
- 출처: [Eurographics 디지털 도서관](https://diglib.eg.org/handle/10.1111/cgf70323), [Wiley](https://onlinelibrary.wiley.com/doi/full/10.1111/cgf.70323), [코드 ModelSheetTo3D](https://github.com/hjyoon02/ModelSheetTo3D), [프로젝트 페이지](https://www.hyejeong.me/publications/modelsheetto3d/)

## 2. 트레이싱(1~2단계 사이 병목)

**Set-of-Mark 시각 프롬프트** (Microsoft, 2023).
- 영역을 기존 분할기로 나누고 번호를 찍어, LLM은 번호만 말하게 한다. 이 방식으로 GPT-4V가 RefCOCOg에서 미세조정 모델을 제로샷으로 넘었다고 보고.
- 우리 trace_review(번호 후보에 넣기·빼기·그대로)와 같은 원리라 방향이 맞다는 근거다.
- **바로 쓸 곳: 색 군집 → 재질 묶음 검토.** 들소 옆 귀 분홍이 '얼굴'에 묶인 원인은 묶음이 기준색 최근접으로 자동 처리되고 LLM이 보지 않기 때문이다. 군집마다 번호를 찍은 그림을 주고 LLM이 "군집 7 = 귀 안" 같은 묶음만 답하게 한다. 반증 조건: 합성 색조 변형 벤치마크에서 귀 IoU가 오르지 않거나 다른 부위가 0.01 넘게 떨어지면 기각.
- 출처: [arXiv 2310.11441](https://arxiv.org/abs/2310.11441v2), [코드](https://github.com/microsoft/SoM)

**Visual Sketchpad** (NeurIPS 2024). LLM이 그림 위에 선·상자·표시를 그리며 추론하고, 검출기·분할기를 도구로 부른다. 평균 +8.6%(시각 과제). 핵심은 손으로 좌표를 그리는 게 아니라 도구를 부르는 것이라, 우리가 겪은 "좌표 그리기 약함"과 맞는다. [NeurIPS](https://neurips.cc/virtual/2024/102102)

**일러스트 층 분해** (Workflow-Aware Structured Layer Decomposition 2026, See-through 2026).
- 애니 그림을 선·평면색·그림자·하이라이트 층으로 나눈다. 평면색 층이 곧 영역 마스크다.
- 우리 톤 경계 문제(그림자 톤을 다른 재질로 착각)의 정식 이름이다. 모델은 학습 모델이라 못 쓰지만, "재질 = 평면색, 톤 = 그림자 층"으로 분리해 다루는 설계는 이미 우리 방향과 같다.
- 출처: [arXiv 2603.14925](https://arxiv.org/abs/2603.14925), [See-through](https://arxiv.org/html/2602.03749v1)

## 3. 3D 만들기

**Sketching with Silhouettes** (Rivers·Durand·Igarashi, SIGGRAPH 2010). 부위마다 정면·옆·위 실루엣으로 비주얼 헐을 만들고 CSG로 합친다. 우리 부위별 헐 + Boolean 합치기와 같은 구조라, 방향이 검증된 방식이다. [PDF](https://www-ui.is.s.u-tokyo.ac.jp/~takeo/papers/alec_siggraph2010_silhouette.pdf)

**비주얼 헐의 한계와 단면 사전** (Kim·Ruttle·Dahyot 2013, Tai 외 2004 합성곱 곡면).
- 비주얼 헐은 오목한 곳과 둥근 단면을 되살리지 못한다. 사전(prior)을 더해야 한다.
- 뿔이 판자처럼 나오는 문제가 바로 이것이다. 단면을 "두 뷰 폭에 맞는 타원"으로 두는 쓸기(이전에 남긴 과제)가 이 계열 해법이다. 반증 조건: 합성 뿔(정답 원통)에서 단면 오차가 헐보다 줄지 않거나 실루엣 IoU가 0.95 아래로 떨어지면 기각.
- 출처: [Tai 외](https://diglib.eg.org/items/b9a6e416-b98c-4261-bc12-a64c135f7a89), [Kim 외](https://mural.maynoothuniversity.ie/15118/1/RD_bayesian.pdf)

**Monster Mash / Teddy 부풀리기** (Google, SIGGRAPH Asia 2020, 오픈 소스 C++).
- 닫힌 윤곽 하나를 부풀려 3D로 만든다. 다중 뷰가 필요 없다.
- 쓸 곳: 한 뷰에만 증거가 있는 부위(들소 옆 귀처럼). 지금은 다른 뷰 폭을 지어내거나 빌린다. 거리 변환으로 두께를 sqrt 꼴로 주는 단순 부풀리기는 numpy·scipy로 바로 된다(설치 불필요). 결과는 가정으로 표시.
- 출처: [Google 블로그](https://research.google/blog/monster-mash-a-sketch-based-tool-for-casual-3d-modeling-and-animation/), [코드](https://github.com/google/monster-mash)

**동물 형태 사전** (SMAL, BARC, 3D-Fauna). 네발 동물 메시 틀로 가려진 몸을 채운다. 학습 모델·GPU라 지금 못 쓴다. 해부 보완(amodal)을 규칙 이상으로 키울 때 후보. [조사 논문](https://arxiv.org/pdf/2410.09312)

## 4. LLM 에이전트 3D 모델링과 검사

**3DHarnessBench** (2026-09). 단일 뷰 → 다중 뷰 → 원하는 시점 보기 → Blender 함수 전부 쓰기 순으로 접근을 늘리면 모든 최신 모델이 좋아진다. 다만 폭은 모델마다 크게 다르다. 우리 하네스의 "도구로 재고 다시 본다" 방향의 근거. [arXiv](https://arxiv.org/abs/2609.06535)

**3DCodeBench** (2026-06, 12개 모델). 실패 대부분은 API 오용이고, 렌더가 성공해도 **떨어져 떠 있는 조각**이 흔하다. 생각 예산·여러 번 다듬기가 도움. 실행 환경의 정밀한 되먹임이 필요. [arXiv](https://arxiv.org/abs/2606.01057)
- 적용: 합친 3D 메시의 연결 성분 수·떠 있는 조각 검사를 관문에 넣는다. harness 폴더를 검색해 보니 3D 메시 쪽에는 이 검사가 없다(트레이싱 2D 성분만 있음). 반증 조건 불필요한 순수 검사 추가라 비용이 작다.

**BlenderGym** (CVPR 2025). 사람에겐 쉬운 편집도 VLM은 어려워한다. 생성기-검증기 닫힌 고리에서 검증기 쪽에 추론을 더 쓰는 것이 효과. [arXiv](https://arxiv.org/abs/2504.01786)

**LL3M** (2025), **MeshCoder** (NeurIPS 2025), **SceneCraft** (ICML 2024). 형상을 코드로, 부위별 의미 단위로 쓴다. LL3M은 Blender 지식 검색(BlenderRAG)으로 실행 오류 26% 감소. 우리는 형상을 이미지에서 재서 만들므로 직접 관련은 작다. [LL3M](https://www.alphaxiv.org/abs/2508.08228), [MeshCoder](https://arxiv.org/abs/2508.14879), [SceneCraft](https://arxiv.org/abs/2403.01248)

**VLM 판정의 신뢰도** (2026 여러 편).
- 기준 그림 + 7장 다중 뷰를 한꺼번에 주자 Qwen2.5-VL이 순서만 보고 답했다(순서 바꾸면 100% 뒤집힘). 해법: 두 장씩 비교, 순서를 바꿔 뒤집히는 판정은 버린다.
- 셰이딩 렌더는 깨진 메시를 멀쩡해 보이게 한다. 법선 그림으로 보여야 결함이 보인다.
- 적용: 우리가 LLM에게 그림을 보여 판단시키는 모든 단계(교정 검토, 앞으로 넣을 묶음 검토)에 "순서 바꿔 두 번 묻고 다르면 UNKNOWN"을 넣는다. 사람·LLM 확인용 3D 그림은 툰 렌더 대신 법선 그림도 같이 낸다.
- 출처: [2606.20364](https://arxiv.org/pdf/2606.20364), [3D-DefectBench](https://arxiv.org/pdf/2607.10826), [2606.18451](https://arxiv.org/abs/2606.18451)

## 5. 리깅(뒤 단계)

**UniRig** (SIGGRAPH 2025, 오픈 소스, 상업 사용 허용 라이선스). 뼈대와 스키닝 가중치를 예측. 후속작 SkinTokens. 학습 모델·GPU라 승인 필요. 네발 동물 전용 결과는 못 찾음(UNKNOWN). 뼈대가 틀리면 스키닝이 크게 나빠진다고 함. [코드](https://github.com/VAST-AI-Research/UniRig)

## 6. 우선순위 (내 판단)

| 순서 | 할 일 | 근거 | 설치 |
|---|---|---|---|
| 1 | 군집 → 재질 묶음 번호 검토(LLM은 번호만 답함) + 순서 바꿔 두 번 묻기 | Set-of-Mark, VLM 판정 편향 | 없음 |
| 2 | 3D 떠 있는 조각·연결 성분 관문 | 3DCodeBench | 없음 |
| 3 | 타원 단면 쓸기(뿔) | 비주얼 헐 한계·단면 사전 | 없음 |
| 4 | 한 뷰 증거 부위 부풀리기(가정 표시) | Monster Mash/Teddy | 없음 |
| 5 | 뷰별 작은 변형 허용 + 잔차 보고 | ModelSheetTo3D | 없음 |
| 6 | 무늬(decal) 층 분리 | ModelSheetTo3D 층 분해 | 없음 |

모두 합성 벤치마크의 새 씨앗으로 검증한 뒤에만 기본값으로 넣는다. 들소 한 장의 개선은 채택 근거가 아니다.

## 7. 못 찾은 것 (UNKNOWN)

- ModelSheetTo3D의 정량 결과: PDF가 커서 읽지 못함.
- VLM 자기 교정 고리가 회차를 거듭하며 나빠지는지 직접 잰 연구: 못 찾음(이전에 찾은 Iterative Visual Thinking 79.6→48.7%가 가장 가까움).
- 네발 동물 자동 리깅 성능.
