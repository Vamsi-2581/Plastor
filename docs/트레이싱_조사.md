# 트레이싱 집중 조사와 적용 (2026-10-28)

**결론: 도면 기반 LLM 모델링의 병목은 트레이싱(목표 윤곽 만들기)이었다. LLM 은 부위 이름과 거친 선, 하네스는 픽셀 정밀도와 독립 검사, 사람은 도면이 정해 주지 않는 컷을 맡는다.**

## 1. 조사한 것과 가져온 것
| 출처 | 내용 | 하네스에 적용 |
|---|---|---|
| Potrace(Selinger 2003), VTracer(MIT) | 얼룩 제거 → (색) 영역 → 경계 걷기 → 다각형 단순화 → 모서리·곡선 | 점을 경계에 붙이지 않고 **영역을 고른다**(`region_part`). VTracer 0.6.15 를 설치해 비교: 직접 구현이 합성 평균 0.997 대 0.968 |
| Iterative Visual Thinking(2026) | VLM 에게 겹침 그림을 보여 주고 고치게 하면 정확도 79.6% → 48.7% 로 떨어짐(학습 없이) | 루프는 그림을 보고 고치지 않는다. **도면 기하의 독립 검사 숫자**로 돈다(`trace_loop.py`) |
| IR-SIS(2026, 수술 영상) | VLM 을 정량 지표 기반 평가자로 두고 반복 정제 | 손실 = 독립 검사 합. 한 걸음에 행동 하나, 줄 때만 채택 |
| Rivers 외(2010), 실루엣 일관성 연구 | 직교 뷰 실루엣은 서로 일관돼야 한다 | 정면·옆 **높이 일치(H)**, 거울 전 **좌우 일치(LR)**, 정면·뒤 = 거울 |
| GrabCut·Random walker | 영역 기반 대화형 분할, 초기 상자에 민감 | 같은 영역 기반 생각. 설치 없이 numpy 로 재질 영역 + 띠 규칙 |
| ModelSheetTo3D, See-through | 모델 시트→3D, 일러스트 부위 레이어 분해 | GPU(8~24GB) 필요라 도입하지 않음(로컬 GTX 750 Ti 2GB) |

## 2. 하네스 구조(트레이싱)
1. `trace.py clusters` → 색 군집 미리보기. LLM 이 재질 묶음(`groups_ref`)을 정한다.
2. `trace.py build` → 배경 먼저 → 군집 → 재질 → 얼룩 흡수 → 닫힌 덩어리 배정 → 영역 선택(+톤 경계 컷) → 겹침 해소 → 대칭축 추정·거울 → 뒤=정면 거울 → 마스크·윤곽표·그림·보고(자동 덧붙임 노랑, 도면 근거 없는 컷, LLM 선 컷).
3. `trace_loop.py` → 독립 검사(H, LR)로 설정(claim_off, snap_px, rough_grow)을 바꿔 가며 손실을 줄인다. 못 고친 것은 사람 몫으로 보고.
4. `bench/` → 정답 있는 합성 도면(3D 도형 셀 셰이딩 정사영) 생성기와 벤치마크. 규칙을 바꾸면 **새 씨앗**으로 검증한다(본 장면으로만 맞추면 과적합).
5. `tests/selftest_trace.py` → 사람 지적별 회귀 시험. 대응표는 `docs/수정_기록.md`.

## 3. 다른 도면에 적용할 때 사람이 하는 일
- 군집 미리보기를 보고 재질 묶음 정하기(같은 부위의 음영 톤을 한 재질로).
- 노랑(자동 덧붙임)이 그 부위인지 확인 → 아니면 `claim_off`.
- '도면 근거 없는 컷' 목록 확인 → 합칠지(`merge`) 둘지.
- 루프가 남긴 FAIL 항목 확인.

## 4. 한계
- 합성 도면은 내가 만든 것이라 실제 그림의 다양성(외곽선, 그라데이션, 털 질감)을 다 담지 못한다. 실제 그림 + 정답 세트는 아직 없다(내려받기는 승인 필요).
- 배경색과 색 거리 18 이내인 부위는 지워진다. 같은 재질 하위 부위 경계는 LLM 선 정확도를 넘을 수 없다.
