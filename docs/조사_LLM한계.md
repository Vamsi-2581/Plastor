# 조사: LLM 의 한계와 도구로 보완하기 (2026-10-30)

사용자: "LLM 의 한계를 조사하고 LLM 이 약한 부분을 도구로 보완해라. 그러기 위한 조사도 필요하다."
원칙: **LLM 에게는 범주·이름·관계·선택만, 정밀한 수·위치·세기·시점 합치기는 도구가.** 맡기는 판단마다 능력을 먼저 잰다(K0).

## 1. 약점과 근거(외부 연구 + 이 프로젝트에서 잰 것)
| # | 약점 | 외부 근거 | 이 프로젝트 근거 |
|---|---|---|---|
| W1 | **여러 시점을 하나의 3D 로 합치기** | MultiView-Bench: 15개 최신 모델 모두 어려운 3D 과제에서 불안정, 실패는 축 방향 판별·시점 통합에 몰림([arXiv 2607.08970](https://arxiv.org/pdf/2607.08970)). Ego3D-Bench: 사람과 큰 차이, **추정 3D 좌표로 '인지 지도'를 만들어 주면** 다지선다 +12%·거리 +56%([ICLR 2026](https://iclr.cc/virtual/2026/poster/10008200)). ViewSpatial: 다른 시점을 상상하는 질문에 약함([arXiv 2505.21500](https://arxiv.org/html/2505.21500v1)) | 정면·옆을 머릿속에서 합치는 일은 맡긴 적 없음(헐·맞추기가 함) |
| W2 | **세밀한 지각·세기·작은 부위** | 세기는 여전히 고질적, 시각 증거보다 글 선입견에 기댐([arXiv 2604.10039](https://www.alphaxiv.org/abs/2604.10039)), 도형 종류가 섞이면 세기 실패([arXiv 2510.04401](https://arxiv.org/html/2510.04401v1)), 기초 지각 16개 모델 모두 60% 미만(PerceptionBench). **확대(줌) 도구**를 쓰면 고해상도 질문 향상([arXiv 2506.14821](https://arxiv.org/pdf/2506.14821)), 보조선 그리기(Visual Sketchpad, [arXiv 2406.09403](https://arxiv.org/html/2406.09403v3)) | Laya Vision 셀 셰이딩 정답률 0.53. 재질 묶음 통째 판단 0.81~0.85 |
| W3 | **그림이 줄어들어 들어감** | Claude 는 긴 변 1568px(4.7 이후 2576px)를 넘으면 줄여서 본다, 28px 칸 하나가 시각 토큰 하나([Anthropic 문서](https://platform.claude.com/docs/en/build-with-claude/vision)) | 들소 도면 전체(1000px 넘음)를 한 장으로 보면 귀 안쪽 같은 작은 부위가 몇 칸뿐 |
| W4 | **정밀한 수·좌표** | LLM CAD: 문법은 맞아도 부품 위치가 틀림(정밀 3D 공간 추론 약함, [arXiv 2603.11831](https://arxiv.org/pdf/2603.11831)), 모양은 맞는데 값 하나만 틀림(5.85 → 5.6, [BenchCAD](https://arxiv.org/pdf/2605.10865)). 해법: **LLM 은 연산 종류만, 결정적 풀이기가 좌표**(Embodied CAD), 측정값으로 바깥 고리 검사(CADSmith: 챔퍼 거리 28.37 → 0.74, [arXiv 2603.26512](https://arxiv.org/pdf/2603.26512)) | 보라 삼각형 좌표 그리기 실패 → "좌표를 쓰지 않는다" 원칙 |
| W5 | **스스로 검증 못 함** | 바깥 되먹임 없는 자기 수정은 불안정하거나 오히려 나빠짐, 도구(코드 실행·검색)로 확인하면 고침([CRITIC](https://arxiv.org/pdf/2305.11738)), 검증 프로그램을 짜서 돌리기([ProgCo](https://preview.aclanthology.org/setup/2025.acl-short.73)) | 내가 이번에 두 번 틀림(겹친 구 부피 합, 렌더 가짜 선) → 둘 다 숫자 교차 확인으로 잡음 |
| W6 | **판정 편향·흔들림** | 위치 편향은 우연이 아니며 판정자·과제마다 다름, 답 질 차이가 작을수록 심함([Judging the Judges](https://arxiv.org/html/2406.07791v9)). 다시 물었을 때 같은 답(재현)이 0.95 를 넘어도 위치 편향은 심할 수 있다 = **안정 ≠ 옳음**, 재현·순서 바꿈·우연 보정 일치(카파)를 따로 재야([arXiv 2606.19544](https://arxiv.org/pdf/2606.19544)) | 순서 바꿔 두 번·두 가족 교차를 이미 씀. 재현율·카파는 안 잼 |
| W7 | **긴 작업에서 무너짐** | 실패는 작업 길이에 따라 비선형으로 쌓이고, 작은 일 성공이 전체 성공으로 안 이어짐, 비계를 더해도 늘 낫지 않음([arXiv 2607.05775](https://www.alphaxiv.org/abs/2607.05775)). 맥락 쌓임 → 목표 잊음·**거짓 완료**·없는 도구 부르기·무한 반복 | 단계 카드(한 장씩), 상태 파일, 루프 엔진이 이미 대응 |
| W8 | **선입견·맞장구** | 시각 증거보다 글 선입견(W2 의 세기 연구) | 현재 답을 보여 주지 않고 묻기(L13) |

## 2. 보완 도구(있는 것 / 새로 만들 것)
| 약점 | 도구 | 상태 |
|---|---|---|
| W1 | 시점 합치기는 도구(헐·맞추기·설계도 숫자 채우기). LLM 에게는 **도구가 잰 3D 숫자 요약**(인지 지도)을 글로 준다: `digest` | 헐·맞추기 있음, **`digest` 새로** |
| W2·W3 | **`zoom`**: 부위 이름으로(좌표 없이) 그 부위 둘레를 원래 해상도로 잘라 키우고, 조각마다 번호(Set-of-Mark)를 붙인 그림. 세기·크기는 LLM 이 그림에서 세지 않고 `digest` 의 연결 성분 수·넓이를 읽음 | **새로** |
| W4 | 도구 층은 좌표를 받지 않음, 값 범위 검사(`api.validate`), 풀이기(맞추기)가 숫자 | 있음 |
| W5 | 판정은 검증기만. **거짓 완료 검사기**: 보고·커밋 글에 PASS 라고 쓴 항목마다 판정 파일(build_steps·장부·자체 시험 출력)이 있는지 | **새로**(훅으로 켜는 것은 사용자 승인) |
| W6 | **`judge` 모음기**: 같은 질문을 순서 바꿔 N 번·두 가족으로 물은 답을 모아 다수결·재현율·순서 뒤집힘 비율·두 가족 카파를 내고, 문턱 미달이면 UNKNOWN | **새로** |
| W7 | 카드 한 장씩, 상태 파일, 루프 엔진, 같은 진단 2번 → 조사 | 있음 |
| W8 | 현재 답 숨기기, 중립 보기 이름 | 있음 |

## 3. K0: 맡기기 전에 재기(기준은 `docs/구현계획_통합.md` K0)
LLM 판단에 기대는 단계(K4 설계도·K5 의도 파악·K6 비평) 전에, 합성 정답으로 그 판단을 잰다. 기준 미달 판단은 LLM 에게 맡기지 않는다(도구·사람으로).
